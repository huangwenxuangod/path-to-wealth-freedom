## 4. 今日 5 个优先长文选题

### 选题 1：Copilot 开始按量算账后，我终于能认真比较 AI Coding 成本了

#### 一句话观点

Copilot 这次最值得普通人关注的不是“官方怎么改套餐”，而是你终于需要把 AI Coding 当成一笔真实成本来算。

#### 为什么适合黄文轩

- 你不是纯工程师，你更像“正在用 AI 工具做项目、做内容、做作品集”的产品型学生。
- 这题能体现你的判断力，因为它不是搬运新闻，而是帮读者做决策。
- 它适合沉淀成长期资料资产，以后可以按月更新。

#### 这个选题属于哪类

- AI 变现 / 资料包 / 模板 / 小工具

#### 可执行边界判断

- 我个人能不能做：能。
- 是否需要企业权限：不需要。
- 是否需要昂贵 API：不需要。
- 是否需要团队：不需要。
- 是否能用普通账号 / 本地脚本 / 简单页面 / 公开资料完成：能，用官方定价页和文档就能完成第一版。
- 1 天内能完成到什么程度：能完成 `一张成本表 + 一篇收藏型长文 + 一个下载版资料包`。

#### 强制学习清单

- 看懂 GitHub Copilot 新计费结构
- 看懂 GitHub Docs 里的模型与价格说明
- 定义 3 类用户：学生党、轻度用户、重度用户
- 对比 Copilot、Codex、Cursor 在“预算感知”上的差异
- 做出一张“什么时候继续用 Copilot，什么时候该换”的判断表
- 把这套判断写成读者能照抄的模板

#### 必须搞懂的概念

- `usage-based billing`：按实际使用消耗计费，不再只是固定月费心智。
- `AI credits`：GitHub 用来统一不同模型与能力消耗的计量单位。
- `重度用户成本不可控`：不是说一定贵，而是你必须开始算。
- `工具切换成本`：换工具不只是价格问题，还有习惯和工作流迁移成本。

#### 长文主线：我要怎么学，怎么把学到的东西填进文章

- 这篇文章的开头钩子：以前我用 AI Coding 工具，更多是“先用再说”；但 GitHub 这次改计费后，我第一次必须认真算这笔账。
- 我今天要先学什么：先把官方 changelog 和 docs 看懂，不要一上来写情绪文。
- 我学的时候要记录什么：哪些能力会额外消耗、哪些用户最容易踩坑、哪些描述容易让人误解。
- 我需要做哪一个最小实验：做一张 `学生党 / 普通使用者 / 重度用户` 的成本判断表。
- 实验过程里要截图 / 记录哪些证据：GitHub Blog 更新页、Docs 定价页、你自己整理出的判断表。
- 哪些内容适合写成“我踩的坑”：一开始只看 changelog，不看 docs，很容易误判实际使用成本。
- 哪些内容适合写成“普通人可复制步骤”：先看官方规则，再按自己 usage pattern 套进判断表。
- 哪些内容适合写成“我的判断”：不是所有人都该立刻迁移，但从现在开始不能不算账。
- 哪些内容适合写成“变现启发”：你可以把这类“工具选择决策表”做成长期栏目或资料包。
- 文章结尾应该引导读者做什么：让读者先盘点自己一周最常用的 AI Coding 场景，再决定要不要换工具。

#### 文章血肉填充提示

- 应该引用哪些信源事实：GitHub Blog changelog、GitHub Docs 定价页

### 选题 1：实测阿里"语构"——普通人 10 分钟做 App，真的假的？

**一句话观点**：阿里达摩院的"语构"平台把 Vibe Coding 的门槛拉到最低——不需要写代码，一句话就能生成完整应用。但「能做」和「能用来赚钱」之间还有很长的路，我帮你走一遍。

**为什么适合黄文轩**：AI Coding 实操 + 内容增长 + 降低门槛吸引新人。正好对标我的定位：大学生用 AI 做项目。

**类别**：AI Coding / Vibe Coding 工具实测

**可执行边界**：
- ✅ 实测语构平台生成 3 个不同类型应用（工具类 / 游戏类 / 内容展示类）
- ✅ 对比：语构 vs Cursor vs Claude Code 的入门体验
- ❌ 不做企业级应用评测
- ❌ 不推荐付费方案（先免费测）

**强制学习清单**：
1. 阿里达摩院"语构"平台的注册、入口、基本操作
2. Vibe Coding 的核心理念：用自然语言描述需求 → AI 生成代码

4. 判断一个 AI 生成的应用是否可用的 5 个标准
5. 从 Demo 到可发布的最小路径

**核心概念**：
- **Vibe Coding**：不以写代码为核心，而是通过自然语言描述"感觉"和"意图"，让 AI 生成完整应用。关键词：直觉式创作。
- **语构的差异化**：内置大模型 + 文生图 + 实时数据 API，不需要自己搭后端。

### 选题 2：我让 Claude Code 动态工作流帮我管一群 AI Agent——实测报告

**一句话观点**：Anthropic 在 Claude Opus 4.8 中给 Claude Code 加了一个"动态工作流"功能——一个 Agent 能规划任务、派发并行子 Agent、验证输出、汇总报告。这不再是一个写代码的工具，而是一个 AI 项目经理。我测了，效果比想象中好。

**为什么适合黄文轩**：AI Coding 实操 + Agent 工作流，正好展示"05 后 AI 项目实验者"的技术深度。用 Claude Code 管 Agent 这个角度，目前中文 AI 自媒体里还没人系统写过。

**类别**：Agent / 工作流自动化

**可执行边界**：
- ✅ 实测 Claude Code 动态工作流：让它管理多个子 Agent 完成一个完整项目
- ✅ 对比：有动态工作流 vs 无动态工作流的效率差异
- ✅ 输出可复用的 Prompt 模板
- ❌ 不做 Anthropic 新闻搬运
- ❌ 不讨论 IPO 话题（那是财经号的事）

**强制学习清单**：
1. Claude Code 动态工作流的基本原理和使用方法
2. 如何设计一个"主 Agent → 子 Agent"的任务分解
3. 动态工作流 vs 传统串行 Agent 的区别
4. 什么任务适合用动态工作流？什么不适合？
5. 子 Agent 之间的通信和结果合并机制

**核心概念**：
- **动态工作流（Dynamic Workflows）**：Claude Code 新增功能，允许用户规划工作 → 运行并行子 Agent → 验证输出 → 报告结果。针对大型代码库（数十万行）设计。
- **与普通 Agent 的区别**：普通 Agent 是一个 AI 干活；动态工作流是"一个 AI 管一群 AI，它们同时干活然后汇总"。
- **现实类比**：就像一个项目经理同时派 3 个人去干不同的事，而不是一个人干完一件再干下一件。

**长文主线 / 骨架**：
1. 开头：Anthropic 又发新模型了，但我关注的是另一个东西
2. Claude Opus 4.8 一句话带过（不提参数不提跑分）
3. 进入正题：动态工作流到底是什么？我画了一个图
4. 实测：让 Claude Code 用动态工作流做一个中等规模项目
5. 拆解：主 Agent 怎么规划、子 Agent 怎么并行、结果怎么合并
6. 对比：同样的项目，不用动态工作流要多久？
7. 判断：这个功能到底改变了什么？谁最需要？
8. 结尾：我整理了一个"动态工作流 Prompt 模板"，免费送你

**文章血肉提示**：
- 一定要画图（流程图），纯文字讲不清楚并行逻辑
- 实测项目选"做一个个人博客的全栈应用"——规模适中、读者能理解
- 对比环节用时间线展示：串行 vs 并行的耗时差异

**读者价值**：
- 正在用 Claude Code 的开发者 → 学会用动态工作流提效
- 对 Agent 好奇的人 → 直观理解"AI 管 AI"是什么体验
- 想做 AI Coding 内容的人 → 拿到一个选题角度

### 选题 3：Google 说"软件将变得即用即弃"——这对我们意味着什么？

**一句话观点**：Google I/O 2026 上，Jeff Dean 扔了一个炸弹："软件将变得即用即弃。AI 按需生成，用完删除。"我把这句话拆开看，发现它可能比 GPT-5 更能改变普通人的工作方式。而最能抓住这个变化的人，可能不是程序员，而是会用 AI 的产品经理和内容创作者。

**为什么适合黄文轩**：这是一个"趋势解读 + 个人判断"型选题。不需要写代码，但需要理解 Agent 和 AI 产品逻辑。适合展示"AI 产品实验者"和"AI 自媒体"的双重定位。

**类别**：AI 产品经理 / 产品设计趋势

**可执行边界**：
- ✅ 深度解读 Google I/O 的核心观点 + 个人判断
- ✅ 结合 Claude Code 动态工作流、Qwen3.7 Hybrid-Agent 等案例佐证
- ✅ 给出普通人的 3 个行动建议
- ❌ 不做纯新闻搬运
- ❌ 不讨论技术实现细节

**强制学习清单**：
1. Google I/O 2026 关于"Ephemeral Software"的完整论述
2. Gemini Spark 24/7 Agent 的产品逻辑
3. Antigravity SDK（多 Agent 编排底座）的设计思路
4. "软件即用即弃"对 3 类人的影响：开发者 / 产品经理 / 内容创作者
5. Agent 时代的 3 个新角色：Agent 设计师 / 工作流建筑师 / 知识资产管理者

**核心概念**：
- **Ephemeral Software（即用即弃软件）**：AI 根据你的需求实时生成软件界面和功能，用完就消失。不需要安装、不需要更新、不需要维护。
- **你的数据、业务上下文和指令集才是永恒的资产**——这才是关键。软件消失了，但你的需求描述、工作流程、数据积累不会消失。
- **案例**：Google 一夜之间用 Gemini 3.5 把内部 Python 工具链翻译为 Go，速度提升 10-20 倍。

### 选题 5：AI 搜索时代，你的内容正在被吃掉还是被引用？（GEO 实测）

**一句话观点**：我用 2 个小时做了一个实验：在 4 个 AI 搜索引擎（Perplexity / 秘塔 / 天工 / Kimi）里搜我自己写过的选题，看看我的文章有没有被引用。结果让我出了一身冷汗——有的内容完全被 AI 吃掉了，有的被引用了但没署名。AI 搜索时代，内容创作者需要学一门新技能：GEO（生成引擎优化）。

**为什么适合黄文轩**：这是我"内容增长"方向的核心议题。AI 搜索正在吃掉传统搜索的流量，公众号创作者必须理解这个变化。

**类别**：GEO / SEO / AI Search

**可执行边界**：
- ✅ 实测 4 个 AI 搜索引擎对同一选题的回答
- ✅ 分析：AI 引用了哪些信源、为什么引用、没引用什么

- ❌ 不做 SEO 技术教程（那是另一个领域）

5. 行动指南：公众号创作者如何让内容被 AI 引用？

   - 数据必须标明来源
   - 案例必须有具体细节
   - 结构要清晰（AI 更容易理解结构化内容）

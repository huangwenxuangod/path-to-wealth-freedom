# 一个人干翻 16 家店铺的公司：利润北极星信息差手册

> 来源：对一家真实亚马逊卖家公司 ERP（ThinkPHP + Layui + MySQL）全模块静态代码逆向（2026-07-30），所有公式/阈值均有 `file:line` 依据。
> **本手册视角**：我不是来分析这家公司、也不是来找产品机会的。我是要**一个人下场做电商，以"净利"为唯一北极星，去复刻甚至干翻这家公司**。所以下面每一条信息差，都先回答两件事：① 它怎么影响我的利润；② 我作为单人怎么用、怎么靠它赢。

---

## 北极星宣言（先对齐，再看下文）

**唯一目标 = 净利。任何动作先问一句："这增加净利吗？"答不上来就别做。**

- 这家公司用一整套系统对冲"规模带来的复杂度"。我一个人没那个体量，但我有它永远没有的东西：**零决策延迟、零人力成本、零沉没成本包袱、可以只打透一个窄 SKU**。
- 他们的代码把"老运营用真金白银试出来的规则"固化了。这些规则就是信息差——我必须偷，但他们的"规模打法"不能直接抄。
- **不要正面比规模，要比两个东西：单位利润（每单净赚多少）+ 现金周转速度（同样的钱一年转几趟）。** 这两项是单人能干翻大公司的唯一战场。

## 第一部分：生死线 —— 一单到底赚不赚钱

> 这是全文最重要的一段。看不懂这段，后面全白搭。新手死，九成死在"以为自己赚钱，其实每单都在亏"。

> ⚠️ **关键勘误（来自六路深挖，必须先看）**：第一部分的护栏公式 `available` 算的是"这一单**还能砸多少广告钱**"，**不是**"一单**净赚多少**"。代码里它**不含** ① 退款/退货（退货率有监控但不进利润）② 亚马逊预留金(reserve)扣减 ③ 长期仓储费/弃置费 ④ 退货时佣金不退的损失 ⑤ 换汇损耗。实际到手净利明显小于 `available`。
> **单人真实净利公式必须自己补：**
> `净利 = 售价 − 采购 − 头程 − 佣金 − FBA − 广告费 − 退款率 × (采购 + 佣金 + 头程)`
> 护栏公式只管"广告出价不超利润余量"，**别把它当净利看**。

### 1.1 真实利润链（从 `AdProfitProfileService.php` + `AdProfitGuardrailCalculator.php:35-42` 逆出）

一单的净利，不是 `售价 − 采购`。完整链条是：

```
净利 = 售价
     − 采购成本(purchase_cost)
     − 头程运费(first_leg_cost)
     − 亚马逊佣金(referral_fee)
     − FBA履约费(fba_fee)
     − 广告费(随投放浮动)
     − 退款/退款佣金损失(退货率×客单价)
     − 长期仓储费(压货惩罚)
     − 预留金(亚马逊放款时扣的 reserve，约 10%)
```

注意最后两项是新手最容易忽略的"隐形杀手"：**退款不是只退本金，退货的佣金通常不退回；压货超过 365 天亚马逊收长期仓储费（按月收，很狠）；放款时亚马逊还会扣一笔 reserve 慢慢释放。**

### 1.2 广告护栏公式（精确版，`AdProfitGuardrailCalculator.php:35-54`）

```php
$reserve   = min(1.0, max(0.0, $min_profit_rate));        // 最低保留利润率，他们默认 10%
$available = max(0.0,                                       // ← 关键：负数强制压成 0
    $price - $purchase_cost - $first_leg_cost
          - $referral_fee - $fba_fee - $price * $reserve);
$target_acos        = $available / $price * 100;            // 你能容忍的最高广告占比
$safe_cpc           = $available * min(1.0, $conversion_rate);
$recommended_bid_cap= $safe_cpc * 0.8;                     // 出价上限再打 8 折留缓冲
```

**这一坨代码，是这本手册的魂。逐句翻译成人话：**

1. **先锁 10% 净利，再谈广告。** `price × 10%` 是雷打不动的底线，先扣掉。
2. **`available` 就是"这一单能拿来烧广告的钱上限"。** 如果 `售价 − 采购 − 头程 − 佣金 − FBA − 10%净利` 算出来是负数 → `max(0.0, …)` 把它压成 **0**。
   - **这意味着：这个 SKU 不配打广告。打一单亏一单。** 新手常见死法：硬给这种 SKU 烧广告"冲排名"，越冲越亏。
   - 单人对策：`available ≤ 0` 的 SKU，**要么提价、要么降本、要么直接砍掉，绝不开广告。**
3. **`target_acos` 是你能容忍的广告占比天花板。** 真实 ACOS 超过它，你就是在吃本金，不是吃利润余量。
4. **`bid_cap` 的精妙**：每点击出价 ≤ `available × 转化率 × 0.8`。因为要 `1/转化率` 次点击才出一单，所以**每单广告费 ≤ available × 0.8 ≤ available**——你永远不可能在一单上烧掉超过利润余量的广告费。这是一道数学保险丝。

### 1.3 我作为单人的执行动作（今天就能做）

建一张"SKU 利润卡"（一个 Excel 表就够），每个想做的 SKU 填一行：

| 字段 | 含义 | 来源 |
|---|---|---|
| 售价 | 实际成交价 | 竞品/自己定价 |
| 采购 | 单件进货 | 供应商 |
| 头程 | 单件摊运费 | 海运总价÷件数 |
| 佣金 | 类目 referral（通常 8%~15%） | 亚马逊类目表 |
| FBA费 | 履约+仓储 | 亚马逊计算器 |
| 预留净利 | 售价×10% | 自己定 |
| **available** | **售价−以上各项** | **算出来** |
| target_acos | available÷售价 | 算出来 |
| 真实退货率 | 类目平均/实测 | 经验 5%~15% |

**纪律：available ≤ 0 的 SKU 不碰。真实 ACOS > target_acos 的广告立刻收。**

## 第二部分：广告不是"花费"，是"利润余量"的精确投放

### 2.1 红线阈值（`AdOptimizationRuleEngine.php` / `DiagnosticsService.php`）

| 信号 | 阈值 | 含义（对利润） |
|---|---|---|
| ACOS | ≥ 100% | 卖一单亏一单（广告费比毛利还高） |
| ACOS | ≥ 50% | 警告，吃掉大半利润 |
| 零转化 | 点击 ≥ 5 且 0 单 | 危险信号，但**先等 14 天归因窗口再杀** |
| 日预算 | 耗尽 | 错失流量 = 少赚钱 |
| 数据决策门槛 | 点击 ≥ 20 且 订单 ≥ 2 | 否则"数据不足"，**不做任何决策** |

### 2.2 忍字诀（反直觉，但保利润）

- **零转化词别急着杀**：等满 14 天归因窗口。新手一看到零转化就删，往往删在起量前夜。
- **数据不足 = 不动**：点击<20 或订单<2，任何"优化"都是瞎调，只会增加波动、烧钱。
- **加价小步快跑**：有转化且 CPC 低于安全线时 +10% 加价，封顶 `safe_cpc×0.8`，观察 3 天再动。不一把梭。

### 2.3 他们拉什么广告报表（`SubmitV3Reports.php`，每天每店每区域滚近 7 天）

SP/SB/SD 的 campaign 报表 + **search_term（搜索词）报表** + **placement（位置）报表**。

- **搜索词报表 = 金矿**：挖出"花了钱没转化的词"做否定词，挖出"高转化词"加预算。这是广告从亏转盈的最快杠杆。
- **placement 报表**：判断"首页顶部溢价"到底值不值——如果顶部 ACOS 比其余位置高一大截，溢价就是浪费。

**我作为单人的对策（不花一分钱达到 80% 效果）：** 亚马逊后台广告管理器自带 search term 和 placement 视图，免费。我聚焦少数 SKU，每周手动看一次搜索词，把烧钱不转化的否掉、把高转化加预算——大公司 16 店分散精力，反而常有"被忽略的烧钱词"；**这正是单人能捡的钱。**

### 2.4 我能怎么 beat 他们

他们 16 店要管，必然有照顾不到的 SKU；我 All-in 少数 SKU，**每个都卡到护栏线、每周手动扫搜索词**。单位利润（每单净赚）我能做得比他们高——因为我不为"规模"牺牲纪律。

## 第三部分：库存钢丝 —— 断货和压货都杀利润

> 断货 = 排名掉了，前面广告白烧；压货 = 现金死了 + 长期仓储费 + 可能过期/清货折损。两头都是利润杀手。

### 3.1 补货公式（精确，`ReplenishProcess.php:109-137, 520-546`）

```
月均销量 = (近7天销量/7 × 30) × 0.5 + 近30天销量 × 0.5
可售月数 = (FBA可售 + FBA在途 + 欠货空运 + 欠货海运 + 补货空运 + 补货海运) ÷ 月均销量
财务审核上限：海运 3.5 个月库存，空运 3 个月
实发量 = min(申请量, max(0, 上限库存 − 现有全链路库存))
```

**翻译成利润语言：**

- **7天年化×50% + 30天×50%**：既跟近期趋势（新品爬坡/旺季）又不被单周抖动带偏。纯看 7 天会旺季备爆、纯看 30 天会迟钝。
- **分母要把"在途+欠货"全算上**。新手只看 FBA 在库就下单 → 在途的货到了直接翻倍压仓。**压仓 = 现金占用 + 长期仓储费 = 利润漏血。**
- **海运比空运多 0.5 个月上限**：差的那 0.5 月就是海运 lead time 的缓冲。空运快，少垫点也能转。

### 3.2 我作为单人的 beat 点

他们体量大，必须前置大批量备货占现金。我可以用**"小批量、高频补、以海运换现金"**：同样的本金，我一年能转更多趟（现金周转速度↑），单笔压货风险↓。压货少 = 没有长期仓储费 = 利润直接多一块。

**执行**：用一张表算"可售月数"，低于 1.5 月才补，补到不超过 3 个月（海运最多 3.5）。绝不因为"怕断货"而超上限囤。

## 第四部分：周复盘 —— 老板仪表盘（只盯 7 个数）

> 大公司靠周报考核运营；我一个人，周报是我和自己的对账。

### 4.1 他们周报看什么（`WeeklyMskuTemplateParser.php`）

- **周起点是周二**（等亚马逊 Business Report 数据完整）。
- 每 MSKU 每周 **7 个原始指标**：销量、销售额、广告销售额、广告费、流量(sessions)、FBA库存、单位成本。
- **3 个派生指标**：ACOS、转化率(销量÷流量)、库存金额。
- 他们把每行绑到"运营+组长"头上——**指标到人，才有改进**。

### 4.2 我的执行（比他们更勤）

一个人反而能更狠：每周二拉一次自己的 7 个数，对每个 SKU 算 ACOS 和转化率。
- ACOS > target_acos → 收广告或否词
- 转化率掉 → 查主图/价格/差评
- 库存金额涨 → 警惕压货

**优势**：他们要等运营填、等组长审；我当天就能看、当天就能动。速度就是利润。

### 我能赢的 5 条（solo 的天然优势，这是干翻他们的支点）
1. **决策速度**：他们改个出价可能走审批/等运营排期；我秒级。速度 = 抓住窗口期的利润。
2. **聚焦**：他们 16 店分散注意力，必有"被忽略的烧钱 SKU / 被忽略的高转化词"；我 All-in 少数，每个都榨干利润。
3. **零人力成本**：他们养运营/采购/美工，净利被工资吃掉一块；我一人多角色，同样营收我的净利直接高一块。

**核心心法：不比谁店多，比谁"每单净赚更多 + 每块钱转更快"。** 这是单人唯一能碾压规模的维度。

## 第七部分：一个人的落地执行清单（按利润优先级）

**第 0 步（今天）**：建"SKU 利润卡"（照第一部分表格），把你打算做/在做的每个 SKU 算一遍 `available`。`available ≤ 0` 的直接标记"不碰/要改"。

**第 1 周**：把广告护栏落地——哪怕手动，也给每个在投 SKU 算出 `target_acos` 和 `bid_cap`，把超线的广告收住；把第五部分红线贴在显示器边。

**第 1 月**：养成周二周复盘习惯（第四部分 7 指标）；建一张"全链路库存表"算可售月数，低于 1.5 月才补、不超 3 个月上限（第三部分）。

**永久纪律（每条动作前默念）**：
- 这增加净利吗？→ 不能回答就不做
- 这个 SKU 的 available 是正的吗？→ 否就不开广告
- 真实 ACOS 超 target_acos 了吗？→ 超了就收
- 库存压超过 3 个月了吗？→ 超了就是现金漏血
- 断货风险 vs 压货风险，我选哪个更便宜？→ 永远选压货更便宜的一侧（断货丢的是未来，压货亏的是确定）

## 第二部分：六路并行深挖明细（file:line 证据版）

> 以下为 6 路并行 Explore 深挖的硬核结果，全部带 `file:line`。每节先给"他们怎么做"，再给"单人怎么用/怎么赢"。

### 路径 1：单品真实利润成本核算

**他们怎么做**
- 均价 `salesSample()` L113-127：取近 28 天 `item_price×qty/SUM(qty)` 销量加权，**只排除 Canceled/Pending**，把退款单也算进去了 → 均价虚高。
- 头程 `costSample()` L142：只来自手动覆盖表 `weekly_asin_cost_override.first_leg_cost`，**无覆盖=算不出利润**。头程靠人手填整批分摊。
- 佣金/FBA `feeFor()` L162-192：调 `ProductFeesApi`（GetMyFeesEstimate）实时预估，**缓存 7 天**。
- 汇率 `CurrencyConfigModel::getChangeMoney()` L31-41：**月度锁汇**（YYYY-MM 一个价），跨币种直接 `CURRENCY_MISMATCH` 拒绝算（L29-32）。

**单人怎么用/怎么赢**
- 头程漏填 = 利润失真，必须建表自己填；均价把退款算进去了，要单独用"净售价"算。
- **他们连自动调价器都没有**（grep reprice/BuyBox 零匹配，定价全人工拍脑袋）——你也没，但要知道专业卖家也靠人工定价，不是什么黑科技。
- 把退款、头程、长期仓储/弃置、退货佣金不退、换汇损耗、预留金，**全手动补进自己的净利表**（见 1.1 勘误公式），否则北极星指标失真。

### 路径 2：广告竞价 / 否定词 / 搜索词金矿

**他们怎么做**
- 加价 `AdOptimizationRuleEngine.php:48-78`：有转化且 `cpc<safe_cpc` 时 `bid×1.1`，封顶 `min(建议价, safe_cpc×0.8)`，否则"观察3天"不加。
- 深度调价 `AdOptimizationDeepRecommendationService.php:69-91`（近7天窗口）：`acos>target` 降 10%；加价需 `GROWTH模式+有转化+acos≤target×0.7+cpc<safe`，`purchases≥2` 加 20% 否则 10%，封顶 `bidCap`。
- 否定词 `AdOptimizationTermRiskService.php:16-26`：**当日** `点击≥5且0单`→建议否定精准/词组；`ACOS≥50%`→警告；**近7天累计**同条件→DANGER。**注意：只产建议，需人工确认才否，不自动提交。**
- 14 天归因：全系统用 `purchases14d/sales14d` 字段，零转化规则文案明确"先观察归因窗口"——不满 14 天不出手。
- 报表 `SubmitV3Reports.php:17-24`：每日拉 SP/SB/SD × campaign + SP 的 advertised_product/ad_group/targeting/**search_term**/**placement** 六维。

**单人怎么用/怎么赢**
- 免费后台可复刻 80%：搜索词报表筛"点击≥5且0单"手动加精准否定；ACOS≥50% 降竞价；后台默认 14 天窗口，不满 14 天不否；安全 CPC 纸笔算（可用利润×转化率，封顶×0.8）。
- **他们 16 店必有照顾不到的烧钱词**——单人聚焦少数 SKU 每周扫一次搜索词，捡的就是这部分钱。

### 路径 3：补货 / 库存状态机 / 现金流

**他们怎么做**
- 月均 `calculateVendibilityMonths` L123-124：`月销7=近7天/7×30`；`月均=月销7×0.5+近30天×0.5`。
- 可售月数分母 L129-134：`FBA可售+在途+欠货空运+欠货海运+补货空运+补货海运`。
- 财务上限 `calculateFinanceCheckQuantity` L523-546：`海运3.5月/空运3月`；`上限=floor(月×近30天销量)`；`批=min(申请, max(0, 上限−库存))`。
- 新品首批 `FIRST_SHIPMENT_LIMIT=20`（L76）、`NEW_PRODUCT_MONTHS=3`（L77）：无销量史新品首批发 `max(0,20−已承诺)`。
- 库存映射 `FbaInventoryModel` L144-147：`fulfillable=可售`、`pendingTransshipment=待调仓`、`fcProcessing=调仓中`、`inboundShipped=在途`。
- 清货/停售 `AUTO_REPLENISH_DISABLED_STATUS=['清货','停售']`（L81）→ 自动禁补；清货是**人工按钮**，非库龄自动。
- 财务库存用人工 `cost_unit`（`inventory_value=数量×cost_unit`），**非移动加权**；头程=`MAX(体积重,实重)×运费率`。

**单人怎么用/怎么赢**
- 把海运 3.5/空运 3 月上限**压到 1~1.5 月**，把首批 20 当"试单上限"；以周销每周小批空运补，30 天上新→回款→再投，跳过 3.5 月海运压货。
- **现金循环从 ~3.5 月缩到 ~1 月，周转快数倍**——同样的钱一年转更多趟，这是单人碾压规模的支点。
- 清货即停补、不堆库龄，避开长期仓储费。

### 路径 4：选品 / 新品 / 爆款判定（最大信息差）

**他们怎么做**
- 产品状态机 `ProductsData.php:42-49`：`待售/在售/清库存/停产/试销/货源待定`；改 `在售` 时自动写 `product_onSale_time` 时间戳（转正节点）。
- 新品首批上限 20（硬编码"新品默认发10个海运" `replenish/purchase.html:79`）——**小批测款是系统硬编码策略**。
- 上不上由销售投票 `erp_sale_comment`：`type=通过/拒绝`，全员通过→待确样；**一人拒绝且全员评完→已拒绝作废**（`SaleComment.php:50-58`）。
- 开发打分字段 `DevelopManage.php:140`：**毛利率、成本、广告占比、市场价、竞品月销**——这就是判断值不值得做的硬指标。
- 月销分级 `PlanLogic.php:236-247`：`≥500爆款 / ≥100热销 / ≥50常售 / <50冷门`；备货系数 `冷门0/常售0/热销2/爆款2.5`（`PlanInventoryModel.php:17-22`）——**冷门几乎不补，爆款 2.5 倍安全库存**。

**单人怎么用/怎么赢**
- 简化版：每新品只发 10–20 个测款；硬门槛（拿货毛利≥40%、广告占比可承受、有竞品月销参照）不达标直接砍。
- 上架 2–4 周后看真实转化，任一红线（差评/侵权/亏损）即"已拒绝"。
- 月销分等定加注：`<50` 不补观察 / `50–100` 维持 / `≥100` 2倍加注 / `≥500` 2.5倍全力供。**北极星=净利**，分等只是加注或砍的信号。

### 路径 5：退货 / 差评 / VOC 利润漏血

**他们怎么做**
- 退货红线 `VocReturnRateNotifier.php:260`：`退货率≥10% → 优先级1`（硬编码不可配，`amz_return_rate_config` 无阈值字段）；算法 `return_rate_30d=退货30天/销量30天`。
- 差评 `NegativeEventService.php:73`：**仅 1~3 星进差评事件**。
- VOC 7 类归因 `FeedbackIssueClassifier.php:16-24`：适配/信号/安装/质量/缺件/描述不符/物流包装；责任分流 `FeedbackNotifier.php:101-136`：**描述不符/安装→只运营背；质量/缺件/物流→加供应链背**。
- 复盘 OA 待办 `due+2天`，`rating≤2` 优先级1。

**系统两处真金白银的漏血（单人必须自己守）**
- **退款不退佣金**：代码从不建模"退款时亚马逊不退佣金、退货运费/FBA退货费卖家自担"，毛利表完全没扣 → 每笔退款净亏一整组。
- **索赔零管理**：grep A-to-z/chargeback/Claim 只命中第三方 SDK，**无任何业务流程**。A-to-z 索赔（全额退+运费+常销毁库存）和 SAFE-T 赔付完全不被捕获——这是亏最猛的出血点。

**单人最低成本防御**
1. 手工盯 ASIN 级 30 天退货率（卖家中心两份报告算 退/销），≥10% 立即下架/改详情/换货。
2. 照搬 7 类归自己做表打标；质量/缺件归供应商（压价/换厂），描述不符归自己（改图改文案）。
3. **真实净利公式把退款率算进去**（见 1.1 勘误）。
4. **每周手动查后台 A-to-z / SAFE-T 报表**——系统零覆盖、亏最猛，单人必须自己守。

### 路径 6：市场情报 / 竞品监控 / 免费可复刻

**他们怎么做**
- 竞品追踪 `CompeteModel.php:12-29`：ASIN/品牌/月销/价格/评论/星级/排名 字段，**纯手动录入**，无 API、无爬取、无自动更新。
- 公开评论批量爬取用 **Outscraper 付费 API**（`deploy/amz_public_review_api.md`）。
- **自家评论/Feedback 用免费 SP-API**（`GET_SELLER_FEEDBACK_DATA`）自动拉。
- **BSR 监控、关键词排名监控、关键词搜索量、竞品销量估算：代码里完全不存在**（grep 无命中）。
- 看板指标 `WeeklyAsinBuilder.php:14-19`：units/sales/sessions/转化率/ad_sales/ad_cost/ACOS/FBA库存/库存金额/cost_unit——全来自**免费** SP-API + Ads API + FBA 报表。

**免费可复刻 vs 需付费**
- 免费（Seller Central + 品牌分析 BA + 前台）：订单/流量/转化率、自家评论与 Feedback、广告 ACOS、FBA 库存、退货率、买家之声、前台 BSR/评论/星级、**BA 的搜索词排名/市场篮子/复购**（代码未用但免费给品牌卖家）。
- 需付费：竞品月销/价格追踪（卖家精灵/Helium）、公开评论批量爬（Outscraper）、关键词搜索量/竞品销量估算（第三方）。

**单人零成本情报 checklist（每周）**
1. 前台+BA 盯目标类目 BSR 波动、竞品评论数/星级/上架日期（等价于他们的手动竞品表）。
2. 品牌分析（免费）：抓搜索词频率排名定关键词；看市场篮子/复购找连带。
3. 业务报表（SC 免费导出）套 `WeeklyAsinBuilder` 那套指标算净利。
4. 退货率+买家之声（免费报表）筛差评痛点反向指导选品避坑。
5. 自家评论/Feedback（免费）1–3 星分类告警。
6. 付费仅建议一项：要做竞品销量估算/评论批量监控再上卖家精灵/Outscraper；否则前 5 步零成本足以以净利为北极星做选品定价。

> **核心信号**：这家公司所有"自己店"的情报都靠免费 SP-API/后台；外部竞品情报要么人工抄、要么 Outscraper 付费；关键词/销量估算类完全外包第三方。**单人用免费资源能复刻约 80%，差的是竞品量化数据**——而这恰恰是你用"多看竞品前台+BA"就能补的。

# Seedance 2.0 Skill OS 深度解析

> 目的：搞清楚「Seedance 2.0 Skill OS」到底是什么、怎么架构的、哪些设计能直接复用进我们的「通用爆款短视频生成 Skill」。
> 调研来源：GitHub 仓库 Emily2040/seedance-2.0、腾讯云开发者、windflash、txtmix、jamecling、aipuzi 等 2026 年公开分析文章。

---

## 0. 先把两件事拆开（这是理解的前提）

绝大多数人混淆了下面两个东西，必须先切干净：

| | Seedance 2.0（模型） | Seedance 2.0 Skill OS（这个项目） |
|---|---|---|
| 是什么 | 字节跳动 SEED 团队的**商业专有视频生成模型** | Emily2040（独立制片人）做的**开源 Agent Skill 包** |
| 开源吗 | 否，权重不公开，本地跑不了（需 H100/A100 集群） | 是，GitHub 免费开源 |
| 你怎么用它 | 通过官方平台：即梦/Dreamina、豆包、火山引擎 Ark API（模型 ID `doubao-seedance-2-0-260128`） | 作为「技能包」加载进支持 Agent Skills 结构的 AI 助手（Claude custom skills / Codex 等） |
| 本质 | 一台越来越强的摄像机 | 教你怎么当制片人的工作流操作系统 |

**一句话**：Seedance 2.0 是相机；Skill OS 是那个告诉你「先想清楚拍什么、怎么拍、给谁看、拍完怎么剪」的制片人。本项目（我们要研究的）是后者——一套 prompt 工程 + 制片工作流的**结构化方法论**，不含模型、不含后端。

模型能力速记（理解 Skill OS 为什么这么设计）：四模态输入——文本 + 图片（最多 9 张）+ 视频（最多 3 段）+ 音频（最多 3 段），单次最多 12 个参考文件，输出 2K、最长 15 秒、原生音画同步。支持 T2V / I2V / V2V / R2V 和首尾帧锁定。

## 1. 它解决的两个系统性问题

作者 Emily2040 在真实制片中踩坑后，把痛点抽象成两个：

**问题一：信息孤岛（平台碎片化）**
同一个「Seedance 2.0」，字节系内部有 5+ 入口（即梦、豆包移动版、小云雀、随变 App、火山引擎 Ark API），每个入口的上传数量、时长、分辨率、价格、区域权限全不一样。今天在网页测通的流程，明天换平台就可能完全用不了。

**问题二：提示词玄学化（形容词堆砌）**
为了「更电影感」，用户堆 `cinematic / ultra-detailed / 8K / masterpiece`——这些词在模型眼里是噪音，稀释注意力权重。真正决定一致性的是：角色绑定、镜头语言、运动节奏、首尾帧锁定——这些硬核参数反被忽略。

**Skill OS 的解法**：把上面两个问题拉回地面——搭一套公开的、可审计的工作流，让 Agent 知道「什么时候该采访用户、什么时候该写短 prompt、什么时候该调技术参考、什么时候该把不安全 IP 重写成安全等价物、什么时候该诊断失败生成」。

## 2. 核心哲学（整座大厦的地基）

仓库首页第一句标语：

> **「Direct the model. Don't micro-manage the frame.」**
> 指导模型，别去逐帧微操。

展开成三条可执行原则：

1. **制片人思维 > 提示词工程师思维**
   创作者瓶颈不再是「模型能不能做」，而是「怎么用好模型」。正确逻辑：先想清楚想表达什么 → 把意图翻译成模型能懂的专业指令（可 AI 辅助）→ 生成后按专业流程判断和修复。

2. **生产对象优先于 prompt（最关键的一条）**
   仓库用一张「八大岗位表」说明：导演产出处理稿/场景节拍/表演意图；摄影指导产出镜头合同；剪辑师产出选片计划……**每个岗位产出的第一行永远不是「提示词」，而是 production object（生产对象）。提示词只是那个生产对象的副产品。**
   → 让 AI 先理解「制片人的工作内容」，再去写服务于那个工作的提示词。

3. **反玄学书写**
   不写空泛美化词，只用直白描述「画面动作 + 叙事目的」。

对比示例（仓库原例）：
- ❌ 堆词写法：「史诗电影镜头，女生低头看信件，氛围感拉满，柔和光影，高清写实」
- ✅ 导演级写法：「中近景平视机位，女生看完信件双手静止，缓慢向内推镜；窗边柔光弱化面部明暗，全程近乎静音，仅保留轻微椅子摩擦声」

## 3. 架构总览：六通道 + 24 子技能 + 59 参考文档

它不是单一 prompt 模板，是结构化技能包，分**六大通道**（职能层）：

| 通道 | 职能 | 例子 |
|---|---|---|
| **Research Sources** | 日期化官方/学术/社区证据，追踪平台状态 | 模型能力 vs 表面行为分离 |
| **Production Spine** | 剧本→分镜→连续性→后期→交付→QC | 从剧本到交付的完整工业管线 |
| **Prompt Router** | 创意访谈/提示词生成/压缩/故障排除 | 把模糊想法变成可执行提示词 |
| **Multimodal References** | 图像/视频/音频/首尾帧参考资产管理 | 角色/环境/运动/镜头/音频分离绑定 |
| **Safety Gates** | IP/肖像/品牌/歌曲检测与重写 | 危险请求→安全创意等价物 |
| **Quality Evals** | 122 个模型在环评估用例 + 13 个离线验证脚本 | 确保输出质量和一致性 |

**子技能数量说法不一**（不同文章写 12 核心 / 15+ / 24 / 30 个），但核心集稳定，见下节。

`references/` 目录存放所有参考文档（工作流、首尾帧指南、重拍协议、模型机制、API 状态、平台矩阵、模型命名、多语言示例、专业制片标准、镜头清单连续性、交付与质检、Agent 兼容性）——**这些不是可选项，是 Skill 运行时主动交叉引用的「事实来源」**。

## 4. 核心子技能逐一拆解

每个子技能都在 `skills/<name>/SKILL.md` 中独立定义，按需调用，不一次性全加载。

### 4.1 入口 / 创意层
- **seedance-interview**：用户只有模糊想法时，通过结构化问答把想法提炼成「聚焦的创意简报」（creative brief）+ 下一步路径。不直接写 prompt。
- **seedance-interview-short**：interview 的轻量版。
- **seedance-sequence**：长故事 / 连接片段集，产出「故事脊柱 + 连续性圣经（continuity bible）+ 片段合同」。负责把长故事拆成可连续生成的片段。
- **seedance-continuation**：继续/扩展/修复尾部，基于「已接受素材」做源门控（source-gated）续写。

### 4.2 prompt 编译层
- **seedance-prompt**：从清晰概念生成「生产就绪 prompt」，完整版约 200 词。
- **seedance-prompt-short**：压缩版，30–100 词，短而有力。
- **seedance-camera**：把导演意图编码成镜头语言（镜头行为/镜头感觉/运动）。
- **seedance-motion**：身体运动/编舞/物理动作，控制事件密度（event density）。
- **seedance-lighting**：情绪/时间/氛围/光线转换，用光线讲故事。
- **seedance-characters**：角色身份/多角色调度，跨镜头角色一致性。
- **seedance-style**：视觉风格设定，不借用既有工作室/系列的安全风格。
- **seedance-vfx**：粒子/破坏/魔法/天气，特效镜头专业表达。
- **seedance-audio**：对话/唇同步/音乐/环境音，各语言对话容量与音频参考行为。

### 4.3 工程 / 治理 / 修复层
- **seedance-pipeline**：API 调用、定价、模型 ID、工作流自动化完整指南。
- **seedance-recipes**：常见类型片（烹饪教程、健身演示、产品展示、动作场景）的快速模板。
- **seedance-troubleshoot**：生成失败时的根因诊断与修复建议（相机/灯光/运动/参考角色/时长/构图/音频/安全措辞逐个变量排查）。
- **seedance-copyright**：请求涉及名人/IP/品牌/受保护音乐时，提供「更安全的创意等价替换」而非直接拒绝。
- **seedance-antislop**：反套路（避免 AI 味/模板化）。
- **seedance-filter**：过滤/质检闸门。
- **retake-protocol（重拍协议）**：五级判定 + 单变量重试预算。生成结果 80% 对时，判断「重做还是保留」，指导只改一个变量重试，不整段推翻。

## 5. 提示词路由机制（按用户状态分流）

这是 Skill OS 最聪明的地方——**它不假设用户来了就直写 prompt**，而是先判断用户处于什么状态，再路由到不同子技能：

| 用户说的 | 加载的技能 | 产出 |
|---|---|---|
| 「我有个模糊想法」 | seedance-interview | 聚焦的创意简报 + 下一步路径 |
| 「这是一个三段连贯故事」 | seedance-sequence | 故事脊柱 + 连续性圣经 + 片段合同 |
| 「继续这个视频」 | seedance-continuation | 基于已接受画面的续写 |
| 「我知道我要什么场景」 | seedance-prompt | 生产级提示词 |
| 「让它短而有力」 | seedance-prompt-short | 压缩到 30–100 词的提示词 |
| 「生成结果 80% 对，重做还是保留？」 | retake-protocol | 五级判定 + 单变量重试预算 |

→ 同一用户在不同阶段被路由到不同技能，而不是困在「写 prompt」一个界面里。

## 6. 长视频状态管理（核心设计原则）

单次生成只有 5–15 秒，做长故事靠多次生成拼接。Skill OS 用一套严格状态模型解决「接缝断裂」：

```
The project state is the source of truth.        // 项目状态是唯一真相来源
The clip contract is the current production task. // 片段合同 = 当前制作任务
The prompt is a compiled instruction for only that task. // prompt 只是该任务的编译指令
```

工作流：
1. 描述完整创意和结局方式
2. 引擎拆分为连续片段
3. 生成片段 01 → 返回结果或末帧
4. **引擎记录「实际发生了什么」（而非「预期发生什么」）**
5. 基于「真实结尾」写片段 02
6. 重复直到达到计划结局

**关键设计**：续写基于「已接受的生成画面」，而非原始 prompt 的预期。因为模型不一定在预期位置结束——盲目续写原始 prompt 会导致接缝断裂。这是真正的「连续性管理」，不是靠 prompt 蒙，是靠工程化流程管。

## 7. 中文原生书写顺序 + @语法 + 多模态参考分类

**中文书写顺序约定**（Seedance 最彻底的本土化设计）：
`参考素材 → 人物动作 → 机位运镜 → 光线氛围 → 音频音效`
——按这个顺序写，模型理解最准，不用英文电影术语硬翻。

**@ 语法（与模型交互的暗语）**：模型不会自动猜素材用途，必须显式告诉它：
- `@图片1` 作为首帧、定画风
- `参考@视频1的运镜方式`
- `@图片1 中的女生作为主角`
- `@音频1 作为配乐，对齐画面节奏`
- `无文字叠加，无水印`（负向）

**多模态参考分类**（按用途绑定，而非混在一起）：
- 身份参考（identity）
- 环境参考（environment）
- 运动参考（motion）
- 摄像机节奏参考（camera rhythm）
- 音频节奏参考（audio rhythm）
- 风格参考（style）

角色一致性实操（仓库原法）：第一次生成 → 保存最满意镜头截图 → 第二次把截图作 `@参考图` 上传 → 提示词写明「@第一个镜头的女生作为主角，保持服装和脸部一致」。

## 8. 评估与质检

- **Quality Evals 通道**：122 个模型在环（model-in-the-loop）评估用例 + 13 个离线验证脚本。
- 交付/质检覆盖：帧率、画幅比、裁切、色彩、响度、字幕、元数据、命名规范、人工质检清单。
- **Safety Gates**：IP/肖像/品牌/歌曲检测，危险请求自动重写成安全创意等价物（不拒绝，而是「换一种安全的说法保留创意功能」）。

## 9. 对我们的「通用爆款短视频生成 Skill」的借鉴（最实用部分）

下面是能直接搬/改进我们 skill 的设计，按价值排序：

### 9.1 直接复用
1. **按用户状态路由**（§5）：我们的 skill 第一件事也该判断——「模糊想法」vs「清晰概念」vs「要压缩」vs「失败要修」，路由到不同处理分支。比一上来就写 prompt 聪明得多。
2. **创意简报先行（interview 思路）**：模糊想法先产出「创意简报」（品类/时长/平台/钩子/情绪转折/参考图状态），再编译 prompt。对应我们的「阶段 1 病毒脚本」前置。
3. **生产对象优先**（§2-2）：先定义「这场戏的戏剧功能/情绪转折」，再写镜头。和我们「切镜落点=情绪转折」完全同构。
4. **中文书写顺序**（§7）：`参考素材→人物动作→机位运镜→光线氛围→音频音效` 直接作为我们每段 prompt 的内部组织顺序。
5. **@参考图分类系统**（§7）：有图时标注 `@图1(身份)` `@图2(环境)`，注入 identity-lock。和我们资产一致性阶段一致。
6. **重拍协议 / 单变量重试**（§4.3 retake-protocol）：写进 skill 的「失败修复」章节——生成不满意时只改一个变量（运镜/光/时长），不整段推翻。对应我们调研文档的「单 shot 预备 3–5 次重生成，单变量修改」。
7. **troubleshoot 诊断树**（§4.3）：生成翻车时按「相机→灯光→运动→参考→时长→构图→音频→安全」逐个变量排查。直接搬成我们的自检/修复清单。
8. **反玄学书写**（§2-3）：明确禁止 `cinematic/8K/masterpiece` 空词，只写动作+叙事目的。直接写进我们 skill 的「禁忌」。

### 9.2 改了再用（适配 15–45s 爆款，而非长片影视）
9. **不照搬 sequence/continuation 的长片状态机**：那是给 5–15 分钟连续剧的。我们做 15–45s 单条，不需要「项目状态是真相来源」那套重型连续性管理——但「续写基于真实末帧而非 prompt 预期」这一点可以轻量化保留（多段拼接时以实际末帧作下一段首帧）。
10. **Safety Gates 改成平台风控**：原版防 IP/名人；我们额外要防「公域直喊代充/引流被限流」。把「危险请求重写成安全等价物」的逻辑，改成「硬广重写成软植入内容」。
11. **recipes 改成爆款类型模板**：原版是烹饪/健身/产品展示；我们换成吐槽/科普/种草/CP/剧情五类的爆款结构模板（Hook→转折→CTA）。
12. **评估用例轻量化**：原版 122 用例太重。我们用「自检清单 8 条」替代（前 3s 钩子、pattern break、情绪转折、六层完整、风格锚一致、声音先行、字幕、CTA）。

### 9.3 不搬（边界）
13. **不引入 LangGraph/Chroma/Redis**：那是 PenShot 的长片路，我们用不到。
14. **不绑定 Seedance 单一模型**：我们做模型方言 adapter（Kling/Veo/Seedance/Hailuo/Sora），原版是 Seedance 专用。
15. **不做八大岗位完整工业管线**：我们只做「想法→爆款生成包」，调色/本地化/交付 QC 那层交给用户后续人工。

---

## 10. 结论：它给我们的核心启示

Seedance 2.0 Skill OS 的本质不是「更好的提示词模板」，而是**把专业制片工作流变成可审计、可复现、可被 Agent 执行的流程**。它证明了三件事，正好支撑我们的 skill：

1. **分阶段 / 按状态路由 > 巨型 prompt**：同一个任务，不同阶段用不同子技能。
2. **导演意图（情绪/镜头/光/音频）驱动 > 形容词堆砌**：空词是噪音。
3. **资产与参考图标签系统 + 一致性注入**：解决角色漂移的共识解。

我们做「通用爆款短视频生成 Skill」时，把它的「导演思维 + 状态路由 + 重拍协议 + 中文书写顺序」吸收进来，再叠加我们独有的「病毒留存工程（Hook/pattern break/loop）+ 模型方言 adapter + 15–45s 精炼约束」，就是现有开源都缺的那块拼图。

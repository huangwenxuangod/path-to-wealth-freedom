## 1\. MiniMax Sparse Attention

![Image](https://pbs.twimg.com/media/HKu_ynzWwAAvghM?format=png&name=large)

超长上下文已经是智能体、代码库级推理、多模态工作流和持久记忆绕不开的核心需求，但密集 softmax 注意力机制仍让百万级 token 的部署成本居高不下。MiniMax Sparse Attention（MSA）在 Grouped Query Attention 之上引入块级稀疏性，并配一个轻量级路由分支，由它决定每个 query 组真正该关注哪些 KV 块。

- **双分支注意力设计：** 索引分支（Index Branch）给整段因果上下文打分，针对每个 GQA 组独立挑出 Top-k KV 块；主分支（Main Branch）只在这些被挑中的块上做精确稀疏注意力。
- **硬件感知实现：** 论文把稀疏模式与 GPU kernel 协同设计，用无 exp 的 Top-k 选择和面向 KV 的外积稀疏注意力，提升块粒度访问下的 tensor core 利用率。
- **大规模下显著加速：** 在一个 109B 参数的原生多模态模型上，MSA 在 1M 上下文场景把单 token 的注意力计算量砍掉 28.4 倍，同时性能对齐 GQA。配套 kernel 在 H800 上拿到 14.2 倍预填充和 7.6 倍解码的端到端加速。
- **为什么重要：** 长上下文只有在服务成本足够低时才有意义。MSA 的吸引力在于：机制保持简洁、训练直接落到生产级模型里、推理 kernel 开源，并已驱动发布的 MiniMax-M3 模型。

[论文](https://arxiv.org/abs/2606.13392) | [推文](https://x.com/MiniMax_AI/status/2065436935188058208)

## 2\. Self-Harness

![Image](https://pbs.twimg.com/media/HKu_9jyWAAAq8bf?format=png&name=large)

大多数智能体脚手架（agent harness）都由人工一次性搭好，然后就冻结起来——尽管底座模型一直在更新。本文提出 Self-Harness：让一个 LLM 智能体自己改进自己的运行脚手架，也就是围绕基座模型搭建的 prompt、工具、记忆与编排逻辑，全程无需人类工程师或更强的外部智能体介入。每个模型都有自己特有的失败模式，系统就专门挖掘这些模型独有的弱点，并把它们转成具体可执行的脚手架修改，而不是泛泛的建议。

- **三阶段自我改进闭环：** Self-Harness 先做 Weakness Mining，把执行轨迹聚类成模型特有的失败模式；再做 Harness Proposal，针对这些失败生成多样但最小化的修改；最后 Proposal Validation，在保留集和留出集上做回归测试，只有通过的修改才会落地。
- **多个基座模型上一致提升：** 在 Terminal-Bench-2.0 上，所有测试模型的留出集通过率都涨了——MiniMax M2.5 从 40.5% 升到 61.9%，Qwen3.5-35B-A3B 从 23.8% 升到 38.1%，GLM-5 从 42.9% 升到 57.1%。
- **把弱点变成修改：** 闭环不会堆砌泛泛的指令，而是把每种观察到的失败模式转成对记忆、工具或 prompt 的精准修改，论文报告的相对改进最高可达 138%。
- **为什么重要：** 模型越来越多、迭代越来越快，给每个模型手工调一套脚手架撑不住。Self-Harness 证明脚手架本身也能自适应，缩小了"冻结的脚手架"和它所包裹的模型之间的差距。

[论文](https://arxiv.org/abs/2606.09498) | [推文](https://x.com/omarsar0/status/2064429834999304247)

## 3\. Agents' Last Exam

![Image](https://pbs.twimg.com/media/HKvAAPHWoAAex8F?format=jpg&name=large)

来自 Berkeley RDI 的 Agents' Last Exam（ALE）是一个持续演进的评测基准，专门用来衡量智能体能否完成真正有经济价值的工作，而不只是把学术考试考好。它由 250 多位行业专家共同搭建，把 1000 多项可验证任务映射到美国联邦职业分类体系，拆成 13 个行业集群下的 55 个子领域。每道题都有客观、可校验的结果，因此完全不需要主观的人工评分；任务池本身也设计成可以持续扩充，新工作流一进来就能挂上去。

- **扎根真实职业：** 任务以 O\*NET 和 SOC 2018 为参照，覆盖非体力劳动行业，明确瞄准智能体真正会落地的专业工作流，而不是谜题式的问题。
- **三层难度阶梯：** 工作被切成 Near-Term、Full-Spectrum、Last-Exam 三档，让基准同时跟踪近期可用性和硬核多步工作的长尾。
- **离饱和还很远：** 最难一档在主流脚手架上的平均完全通过率只有 2.6%，哪怕是 Codex + GPT-5.5 这种强力组合，在最易档也拿不到 50%，最难档不到 10%。
- **为什么重要：** 现有基准上的高分并没有转化成有经济意义的部署。ALE 把评测重新对准"可验证、专家把关的真实工作"，并给出一个会随智能体进步而不断抬高的标尺，天然抗饱和。

[论文](https://arxiv.org/abs/2606.05405) | [推文](https://x.com/dair_ai/status/2062916866235068607)

## 4\. How AI Agents Reshape Knowledge Work

![Image](https://pbs.twimg.com/media/HKvAC3vWEAEHAkc?format=png&name=large)

这篇经济学论文基于 Perplexity 的大规模生产数据，研究从对话式助手到自主智能体的转向如何重塑知识工作。它沿着三个维度对比两类系统：Search（对话式助手）和 Computer（通用智能体系统）——自主性、效率、人们承担的任务范围。论文给出一个成本结构模型：智能体承担更高的固定成本和委托成本，但单步边际成本更低，所以只要任务足够复杂，智能体就占优。

- **实际跑起来，自主性差别很大：** Computer 单会话平均跑约 26 分钟的自主机器工作，Search 只有约 33 秒；单查询的不满意度，Computer 比 Search 低 55%，1.3% 对 2.9%。
- **效率大幅提升：** 在匹配任务上，Computer 把完成时间从 269 分钟压到 36 分钟，时间省 87%，相对人类搭配 Search 工作，成本省约 94%。
- **任务范围向上迁移：** 智能体查询的认知复杂度更高，抽象/非例行工作占 71%（Search 为 53%），创造级工作量翻倍，且常把跨职业边界、互相依赖的子任务打包在一起。
- **为什么重要：** 数据给出一个干净预测：随着委托的固定成本下降，智能体把"可负担的价值边界"往更高价值、多步的知识工作上推——而这恰好是采用率增长最快的方向，研究期内增长到首周量的 84 倍。

[论文](https://arxiv.org/abs/2606.07489) | [推文](https://x.com/omarsar0/status/2064076252584222933)

## 5\. Agentopia

![Image](https://pbs.twimg.com/media/HKvAK4oXAAAt262?format=png&name=large)

Agentopia 是迄今最具野心的智能体社会测试场之一——79 页的发布稿把 100 个 LLM 智能体放进一个持久世界，让它们生活、建立关系、追逐目标，横跨 10 个模拟年，比之前日级粒度的工作多出几个数量级。作者不仅观察涌现出的社会行为，还把这个仿真本身当作训练信号，通过拒绝采样把模型优化到一个能反映人类福祉的"生活奖励"（life reward）。

- **长程设计为先：** 早期的智能体社会研究只到天级粒度，Agentopia 把单世界推到十年的生命跨度，由此浮现出短时间看不到的非脚本化社交策略和人际动态。
- **仿真即训练信号：** 生活奖励指标被用来微调更拟人化的模型，得到的提升不止留在沙盒里，会迁移到下游的角色扮演基准。
- **可量化收益：** 训练后的智能体在 CoSER Test 上整体提升 15.6%，其中拟人度涨 23.7%，角色保真度涨 16.4%；被同伴尊重的比例高 24.2%，被喜欢的比例高 15.9%。
- **为什么重要：** 单次十年、百智能体的运行要吃掉 137 亿 token 和 56.7 万次 LLM 调用。这种规模本身就是一种表态：智能体研究正在走向"会生活、会学习的群体"——既是研究对象，也是训练数据源。

[论文](https://arxiv.org/abs/2606.07513) | [推文](https://x.com/dair_ai/status/2064075015960875347)

## 6\. The Geometry of On-Policy Distillation

![Image](https://pbs.twimg.com/media/HKvAOJaXYAAnm7A?format=jpg&name=large)

On-policy distillation（OPD，在线蒸馏）已经跻身今年最受关注的后训练配方之一，但多数时候它被当作一个黑盒，模糊地落在监督微调和 RL 之间。本文把它拆开：从参数几何层面刻画在线蒸馏到底怎么动模型的权重，并主张在线蒸馏不是 SFT 与 RLVR 的中点，而是一种独立的更新类型。

- **触及的参数更少：** 相比 SFT，OPD 的更新只动极少数参数，并且大体避开了权重空间中的主成分方向，这正好能解释它为什么样本效率高。
- **训练初期子空间就锁定：** OPD 的累计更新在训练早期就迅速坍缩进一个窄而低维的子空间，而不是像 SFT 那样向多个方向铺开。
- **那个子空间够用：** 把训练约束在早期形成的子空间里，OPD 的性能保留下来，但 SFT 的性能明显下降——说明这个小子空间真的承载了有效信号，不只是统计伪影。
- **为什么重要：** 知道在线蒸馏在权重空间的哪个位置起作用，就把一个流行但理解浅的配方升级成了有机制解释的方法。由此更容易去推理、与其他目标组合、做有依据的改进，而不是靠试错。

[论文](https://arxiv.org/abs/2606.07082)

## 7\. Lookahead Sparse Attention

![Image](https://pbs.twimg.com/media/HKvAQ9mWYAAxsly?format=png&name=large)

长上下文解码被 KV 缓存卡住脖子——它随每个 token 增长，到了极长上下文很快就吃光显存。本文围绕 DeepSeek-V4 提出 Lookahead Sparse Attention（LSA）：不存完整 KV 缓存，而是预测后续解码真正需要的上下文片段，只保留对 query 关键的 chunk。

- **轻量级、可学习的索引器：** 不再"全留着"，由一个小索引器主动挑出下一步生成真正要用的 KV chunk，物理缓存保持小巧，但模型需要的信息不丢。
- **解耦训练，无需加载基座：** 解耦训练策略让索引器能独立训练，不必把完整基座模型加载进来，给大模型加这套机制的成本大幅降低。
- **缓存大幅压缩，质量不降：** LSA 把物理 KV 缓存压到完整上下文的 13.5%，平均准确率还微涨 0.6%；在 500K token 上下文下，KV 缓存开销被砍掉 90% 以上，推理稳定性不受影响。
- **为什么重要：** 超长上下文已经从"玩具演示"的分水岭变成"能否真正可用"的分水岭，瓶颈就在显存。预测"你将要需要什么"而不是"全留着"，是让长上下文跑进真实硬件预算的务实路线。

[论文](https://arxiv.org/abs/2606.09079)

## 8\. Latent Spatial Memory

视频世界模型很难在长程下保持一致，因为显式 3D 记忆通常要在像素空间走一圈、代价很高。Mirage 反其道，把场景信息直接存进 diffusion 的 latent 空间，靠深度引导的反投影和 latent 空间 warp 维护持久的空间记忆。论文报告：相对显式 3D 记忆基线，端到端生成最高提速 10.57 倍，显存占用降低 55 倍，同时长程空间一致性更好。

[论文](https://arxiv.org/abs/2606.09828)

## 9\. The Consistency Illusion

多智能体辩论的质量，常被"最后大家有没有达成一致"这种表面结果来衡量。本文却指出：输出层面的共识可能掩盖推理层面的深度分歧。作者把智能体的推理轨迹和决策抽象到两个轴（推理相似度、结论一致性）上的四种状态，并标出"分歧性一致"——智能体走到同一个答案，但走的路很不一样。在 600 条内容审核样本上，分歧性一致出现了 118 次，与真正的"分歧状态"分得很开（Cohen's d = 0.80）；按这些类别做路由，在抓高分歧案例上优于只盯着"分歧"指标的方法。

[论文](https://arxiv.org/abs/2606.04223) | [推文](https://x.com/dair_ai/status/2064395355220029696)

## 10\. Beyond Scalar Rewards

奖励模型常把判断压成一个标量，但本文主张人类偏好更适合用分数分布来刻画，提出 Z-Reward：先让模型把推理内化成一个预测分布，再据此打分。一个大型视觉语言教师模型负责做重推理判断，再蒸馏到一个紧凑的学生模型里以便部署。结果是 27B 教师达到 89.6% 的人类偏好准确率，9B 学生以 88.6% 几乎追平。把它当作强化学习信号，相对监督基线带来 41.3% 的净偏好提升，击败 GRPO 等其他奖励方法。

[论文](https://arxiv.org/abs/2606.09076)

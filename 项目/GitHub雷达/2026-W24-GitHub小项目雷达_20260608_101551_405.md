#### 项目类型

AI Agent

#### 为什么值得看

Hermes Agent 不是又一个"套壳 ChatGPT"的 Agent 框架。它的核心差异是**闭环学习**：

1. **自主创建 Skill**：完成复杂任务后，Agent 会自动把经验抽象成一个可复用的 Skill
2. **Skill 自我改进**：Skill 在被调用时会根据效果自我调优，而不是写死
3. **跨会话记忆**：基于 FTS5 全文搜索 + LLM 摘要，Agent 能跨会话回忆你之前交代的事情
4. **定时任务内置**：cron 调度器天然支持"每天帮我整理 GitHub Trending"这类定时作业
5. **不绑模型**：支持 Nous Portal / OpenRouter / OpenAI / Anthropic / Gemini / MiniMax / Kimi 等

这代表了一个趋势信号：**AI Agent 正在从"单次对话工具"进化到"长期运行的自主实体"**。174k Star 不是偶然——它踩中了个人效率自动化、副业接单、AI 实操三个需求的交集。

#### 为什么适合黄文轩

- **大学生 AI 实战家**：安装只需一行 PowerShell 命令，Windows 原生支持，不需要 WSL，不需要 Docker。跑通后就是"我让 AI 帮我做了 X"的实操素材。
- **科技 AI 自媒体**：Hermes Agent 的故事线太好讲了——"一个会自我进化的 AI Agent，我让它帮我写了 7 天公众号，结果它学会了我的文风"。这种内容天然适合公众号长文和 X 线程。
- **AI 产品实验者**：内置的 Skill 系统可以和 Claude Code 的 Skill 生态做对比，产出一篇"Agent Skill 生态对比"的深度内容。
- **可改造空间大**：可以给它写一个"公众号选题 Skill"，让它每天定时搜索热点、生成选题、推送到微信。

#### 可执行边界判断

| 是否需要昂贵 API | 不需要。有免费额度的 Nous Portal 可入门，也可用本地模型 |
| 是否需要复杂部署 | 低。安装脚本全自动，约 5-10 分钟完成 |
| 是否需要团队 | 不需要 |
| 难度分层 | **1 天可改造** |
| 最大风险 | 安装依赖较多（uv、Python 3.11、Node.js、ripgrep、ffmpeg、MinGit），网络不好时安装可能失败；首次配置模型 Provider 需要 API Key |

#### 最小运行路线

1. **第一步**：打开 PowerShell，运行 `iex (irm https://hermes-agent.nousresearch.com/install.ps1)`
2. **第二步**：安装完成后运行 `hermes` 进入交互 CLI
3. **第三步**：运行 `hermes model` 选择模型 Provider（推荐先用 Nous Portal 免费额度或 OpenRouter）
4. **第四步**：在 CLI 中说"帮我查一下今天 GitHub trending 有哪些 AI 项目"，观察它调用工具链的完整过程
5. **第五步**：运行 `hermes gateway` 启动消息网关，扫码绑定微信或 Telegram
6. **第六步**：通过微信发送"帮我总结今天的待办事项"，确认跨平台通信正常

**判断跑通**：通过微信发送指令 → CLI 终端看到 Agent 执行工具调用 → 返回结果到微信。

#### 项目类型

AI Coding / Coding Agent

#### 为什么值得看

Reasonix 代表了 AI Coding 工具的一个新方向：**为特定模型深度优化，而不是通用适配**。

它的核心设计哲学是"Engineered around prefix-cache stability"——DeepSeek 的 prefix cache 能大幅降低 API 成本，但前提是 prompt 结构要稳定。Reasonix 就是为此打造的编码 Agent，在设计和实现上刻意保持了 prompt 的一致性，从而最大化利用 prefix cache，把多轮编码对话的成本降低 50-90%。

这不只是一个"又一个 Claude Code 替代品"，它代表了一个趋势：**模型厂商 + Coding Agent 的深度耦合将成为新范式**。就像 Apple 的软硬一体，DeepSeek + Reasonix 的"模码一体"可能让编码 Agent 的性价比出现数量级提升。

另外，Go 语言写成单二进制文件，安装是 `npm i -g reasonix` 一行的事，不需要 Python 环境、不需要虚拟环境。

#### 为什么适合黄文轩

- **AI Coding 实操者**：Reasonix 是纯 coding agent，跑起来直接能在终端里写代码。作为 AI Coding 栏目素材，它可以和 Claude Code / Codex CLI 做横向对比。
- **内容角度独特**："Prefix-cache 如何让 AI Coding 成本降低 90%"这种技术深度 + 实操验证的内容，在中文 AI 自媒体里几乎没有。天然形成差异化。
- **实战价值高**：日常写小工具、改代码、修 bug 都可以用它，跑通后直接提升自己效率。
- **趋势信号**：如果 DeepSeek + Reasonix 的耦合范式被验证，这可能改写 AI Coding 工具的竞争格局。提前拆解就是提前卡位。

### 项目 3：Webwright——微软 SOTA 浏览器 Agent

#### 项目信息

| 字段 | 内容 |
|------|------|
| 项目名 | Webwright |
| GitHub | https://github.com/microsoft/Webwright |
| 项目页 | https://microsoft.github.io/Webwright |
| Star | ~5,000 |
| 最近更新 | 2026-05-30 |
| 主要语言 | Python |
| License | MIT |
| 一句话说明 | 微软研究院推出的轻量浏览器 Agent 框架：让 LLM 在终端里写 Playwright 代码、执行 bash 命令、查看日志并自我修正，核心仅约 1000 行代码，在长周期网页任务上达到 SOTA |

#### 项目类型

Browser Agent / Computer Use

#### 为什么值得看

Webwright 的设计哲学非常克制且优雅，和市面上 90% 的浏览器 Agent 完全不同：

1. **代码 > 动作**：传统浏览器 Agent 是"截图 → 预测下一个点击坐标"，Webwright 是"写 Playwright 代码 → 执行 → 看结果 → 修改代码"。代码比低级动作更适合表达多步任务、更容易复用、更容易调试。
2. **终端为中心**：所有操作在终端里完成，不需要 GUI。这意味着它可以无缝集成到任何 AI Coding 工作流中。
3. **约 1000 行代码**：Runner ~150 行，模型接口 ~550 行，环境 ~300 行。一个大学生一晚上能读完整个源码。
4. **SOTA 基准**：在 Online-Mind2Web（300 任务/136 网站）上基于 GPT-5.4 达到 86.67% 准确率。这不是玩具项目。
5. **可作为 Skill 安装**：支持 Claude Code / Codex 插件格式，一行命令集成进你的编码工作流。

微软做 Webwright 这个轻量框架，传递了一个信号：**浏览器 Agent 不需要复杂架构，一个终端 + 写代码的范式可能就够**。

#### 为什么适合黄文轩

- **AI Coding 实操者 + 科技 AI 自媒体**：1000 行代码的 SOTA 项目，天然适合"拆解源码 + 解读设计哲学 + 跑通 Demo"的长文形式。读源码的过程本身就是内容。

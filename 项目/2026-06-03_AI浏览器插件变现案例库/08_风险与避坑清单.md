# 08 - 风险与避坑清单

---

## 风险 1：Chrome Web Store 审核不通过或下架

- **风险是什么**：Google 可能因权限声明不当、隐私政策缺失、功能描述不清晰等原因拒绝上架或下架。
- **为什么会发生**：Manifest V3 对权限声明要求更严，AI 插件常涉及网络请求和用户数据处理。
- **怎么规避**：① 权限声明最小化（只声明实际使用的权限）② 提供隐私政策链接 ③ 描述中清晰说明 AI 功能的工作方式 ④ 不收集不必要的用户数据

---

## 风险 2：Manifest V2 即将被淘汰，MV3 迁移成本

- **风险是什么**：如果你基于旧的 MV2 教程开发，插件可能在短期内失效。Chrome 已宣布逐步淘汰 MV2。
- **为什么会发生**：大量旧教程和代码示例仍是 MV2，新手容易踩坑。
- **怎么规避**：① 开发前明确使用 Manifest V3 ② 使用 WXT 等支持 MV3 的现代框架 ③ 关注 Chrome Extension 官方文档的更新

---

## 风险 3：API 成本失控

- **风险是什么**：依赖 OpenAI / Claude API，免费用户太多时 API 费用可能超过收入。
- **为什么会发生**：前端免费版没有用量控制，或者 API 调用过于频繁。
- **怎么规避**：① 免费版严格限制每日调用次数（如 5 次）② 付费版按月订阅 ③ 使用更便宜的模型（如 GPT-4o-mini）处理简单任务 ④ 设置每月 API 预算上限

---

## 风险 4：86.3% 的插件安装量不到 1000——上架不等于有用户

- **风险是什么**：花时间做出插件上架后发现根本没有自然下载。
- **为什么会发生**：Chrome Web Store 的搜索排名机制不利于新插件，加之超过 18 万个插件竞争。
- **怎么规避**：① 不要依赖 Web Store 自然流量 ② 必须通过 Reddit / X / Product Hunt / 小红书等外部渠道主动引流 ③ SEO 优化 Web Store 页面的标题和描述关键词

---

## 风险 5：竞品快速跟进，失去差异化

- **风险是什么**：你的插件火了之后，其他人用 AI 同样可以在几天内做出类似产品。
- **为什么会发生**：AI 降低了开发门槛，Vibe Coding 让复制成本趋于零。
- **怎么规避**：① 专注垂直场景（越细越难被复制）② 通过内容/IP 建立品牌护城河（Build in Public）③ 持续迭代而非一次性交付 ④ 建立用户社群提高迁移成本

---

## 风险 6：付费意愿不足

- **风险是什么**：即使有很多免费用户，也很少有人转化为付费用户。
- **为什么会发生**：插件用户习惯了免费，尤其是效率工具类。付费转化率通常在 1-3%。
- **怎么规避**：① 选有明确商业价值的场景（帮用户赚钱/省时间的比帮用户娱乐的更容易收费）② 免费版给足体验但留有升级动力 ③ 价格不要太高（$5-10/月是甜点区）

---

## 风险 7：Gmail / YouTube 等平台 DOM 变化导致插件失效

- **风险是什么**：如果你的插件依赖注入到 Gmail、YouTube 等第三方页面的 DOM 结构，这些平台更新 UI 后你的插件可能完全失效。
- **为什么会发生**：大平台频繁更新前端，DOM 选择和注入逻辑跟着变。
- **怎么规避**：① 使用更稳定的选择器（data 属性而非 CSS class）② 设置自动检测机制，插件失效时通知用户更新 ③ 监控目标平台更新频率 ④ 优先用官方 API 而非 DOM 操作

---

## 风险 8：数据隐私和合规风险

- **风险是什么**：AI 插件常涉及用户数据（网页内容、输入文本）发送到第三方 API，可能触发隐私合规问题。
- **为什么会发生**：用户不知道数据被发送到 OpenAI 等服务器，GDPR 等法规有严格要求。
- **怎么规避**：① 明确告知用户数据会被发送到 AI API ② 提供本地处理选项（如果可行）③ 不存储用户数据到自己的服务器 ④ 准备隐私政策页面

---

## 风险 9：技术栈选择错误导致后期维护困难

- **风险是什么**：一开始用了不适合的技术栈，后期加功能时成本暴增。
- **为什么会发生**：Vibe Coding 生成的代码可能结构差、可维护性低。
- **怎么规避**：① 能用 Vanilla JS 就不用 React（插件不需要复杂框架）② 如果有经验，用 TypeScript 增加代码可靠性 ③ 代码模块化，每个功能独立文件。

---

## 风险 10：时间投入低估，副业变「负业」

- **风险是什么**：以为 3 天能做完，实际花了 3 周还没上线。特别是遇到 API 调试、UI 细节、审核反复等问题。
- **为什么会发生**：低估了「看起来简单」的功能背后的复杂度，高估了 AI 的代码质量。
- **怎么规避**：① 严格按照 7 天计划，超时果断砍功能（先上线再说）② 第一版只做一个核心功能 ③ 设定每周时间上限（如每周不超过 15 小时）

---

## 风险 11：收入数据夸大，预期管理失败

- **风险是什么**：看到 Gmass 月入 $13 万、Monica 年入过亿的案例，误以为自己也能轻松做到。
- **为什么会发生**：幸存者偏差——只看到成功的案例，忽略了 86.3% 的插件几乎没有用户。
- **怎么规避**：① 把第一个插件当作学习项目，不期望赚钱 ② 设定合理的收入预期：第 1 个月 $0-100 是正常水平 ③ 关注过程指标（安装量、活跃度）而非收入

---

## 风险 12：浏览器扩展权限被滥用导致安全风险

- **风险是什么**：如果代码被恶意篡改或依赖的第三方库有漏洞，插件可能变成安全隐患。
- **为什么会发生**：插件有读取网页内容等敏感权限，攻击者可能通过供应链攻击植入恶意代码。
- **怎么规避**：① 不引入不必要的外部 JS 库 ② 定期审查依赖 ③ 使用 Content Security Policy ④ 避免在插件中执行 eval()

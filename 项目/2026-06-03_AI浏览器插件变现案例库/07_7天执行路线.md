# 07 - 7 天执行路线

> 假设你拿到这份资料包后，选了一个方向（推荐「AI 网页划词改写器」或「跨境电商产品描述生成器」），以下是你接下来 7 天的执行计划。

---

## Day 1：选方向 + 验证需求

- **任务**：从资料包中选定一个方向，快速验证需求是否真实
- **具体操作**：
  1. 从「Top 10 机会」或「可复刻小项目」中选 1 个你最感兴趣的
  2. 到 Reddit / 知乎 / 小红书搜索相关关键词，找到至少 5 条用户抱怨或需求表达
  3. 搜索 Chrome Web Store，找到现有竞品，看评分和差评
  4. 用「需求验证模板」（模板区模板 1）填写验证结果
  5. 决定：做还是换方向？（如果验证不通过，果断换）
- **产出物**：填好的需求验证表
- **判断标准**：找到了 5+ 条真实需求表达；竞品有明显可改进空间

---

## Day 2：搭建开发环境 + 写第一行代码

- **任务**：安装工具，用 AI 生成插件骨架代码
- **具体操作**：
  1. 安装 Cursor（cursor.com，免费版即可）
  2. 注册 Chrome Web Store 开发者账号（$5 一次性）
  3. 了解 Chrome Extension Manifest V3 基本结构（15 分钟看文档）
  4. 在 Cursor 中新建项目，用自然语言描述你的插件需求
  5. 让 AI 生成 manifest.json + background.js + content script + popup 基础代码
  6. 在 chrome://extensions 加载已解压的扩展，确认基础结构能跑
- **产出物**：能加载到 Chrome 的插件骨架
- **判断标准**：扩展图标在浏览器工具栏出现；popup 点击能打开（哪怕是空白页）

---

## Day 3：实现核心功能

- **任务**：让插件能完成最核心的那个功能
- **具体操作**：
  1. 聚焦一个核心功能（如「选中文本→右键→生成改写结果」）
  2. 接入 API（OpenAI / Claude），调通请求和响应
  3. 在 Cursor 中继续迭代代码，修 bug
  4. 测试至少 5 个不同输入，确保输出质量基本可用
- **产出物**：核心功能可用的插件（哪怕 UI 很丑）
- **判断标准**：能让一个朋友试用并成功完成核心任务

---

## Day 4：完善 UI + 交互体验

- **任务**：让插件看起来像产品，而不是 demo
- **具体操作**：
  1. 设计 popup / side panel 界面（参考竞品的 UI 但不抄袭）
  2. 加入加载状态、错误提示、成功反馈
  3. 加入设置页面（API Key 输入、偏好设置）
  4. 加入使用次数统计（为付费版做准备）
  5. 测试边界情况：无网络、API 报错、空输入等
- **产出物**：体验完整的插件
- **判断标准**：陌生人能在不看说明的情况下基本会用

---

## Day 5：准备上架材料

- **任务**：准备 Chrome Web Store 上架所需的所有材料
- **具体操作**：
  1. 制作插件图标（128×128 PNG）——可用 AI 生成或用 Canva
  2. 截取 3-5 张产品截图（1280×800）
  3. 写插件名称、简短描述、详细描述
  4. 如果处理用户数据，准备隐私政策页面链接
  5. 最后检查代码（删除 console.log、确认最小权限声明）
  6. 打包 .zip 文件
- **产出物**：可以提交审核的完整上架包
- **判断标准**：「上架清单」模板中的所有项都已打勾

---

## Day 6：上架 + 准备推广内容

- **任务**：提交审核，同时准备推广内容
- **具体操作**：
  1. 在 Chrome Web Store Developer Dashboard 提交插件
  2. 写 3 条推广文案（X Thread / 小红书笔记 / Reddit 帖子）
  3. 准备 Product Hunt 页面草稿（如果打算上 PH）
  4. 准备「使用教程」截图或 30 秒 Demo 视频
  5. 列出前 5 个要推广的渠道和发布时间
- **产出物**：已提交的插件 + 3 条推广内容
- **判断标准**：提交成功且推广内容可以随时发布

---

## Day 7：审核等待期 + Build in Public 第一篇

- **任务**：发布第一篇 Build in Public 内容，开始积累关注
- **具体操作**：
  1. 选择 1 个平台（推荐 X 或小红书）发布第一篇 Build in Public 内容
  2. 分享你的开发过程、遇到的坑、为什么做这个产品
  3. 如果 Web Store 审核通过了，立即发布上线内容
  4. 如果还在审核，分享「等待审核中」的状态
  5. 开始规划第一个功能更新（根据这几天的思考和反馈）
- **产出物**：第一篇 Build in Public 内容已发布
- **判断标准**：有真实互动（评论/点赞/转发），哪怕只有 5 个

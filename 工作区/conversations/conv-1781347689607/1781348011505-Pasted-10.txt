`项目/GitHub雷达/YYYY-WW-GitHub小项目雷达.md`

# 一、任务目标

生成一份面向黄文轩的每周 GitHub 小项目雷达。

黄文轩的定位是：

* 科技 AI 自媒体
* 大学生 AI 实战家
* 05 后 AI 项目实验者
* AI 产品实验者
* AI Coding 实操者
* 正在用 AI、内容和产品，从 0 到 1 跑通项目、流量和现金流

这个雷达不是普通 GitHub Trending 榜单，也不是 Star 排行榜。

它的目标是：

从 GitHub Trending、GitHub Topics、AI Agent / AI Coding / MCP / 内容增长相关开源项目中，筛出本周最适合黄文轩复刻、讲解、改造、写成长文、沉淀成作品集或内容资产的项目。

最终输出 5 个项目，并选出 1 个“本周最推荐先跑”的项目。

固定栏目定位：

> 本周我发现 5 个普通大学生也能跑起来的 AI 项目

# 二、核心筛选原则

## 1. 不看 Star 崇拜，看实操价值

Star 多不是唯一标准。

优先选择：

* 个人 1 天内能跑起来
* README 清楚
* 有安装步骤
* 有 Demo / 示例 / CLI / UI / API 输出
* 能截图展示
* 能写成教程
* 能改造成小工具、资料包、Skill、Prompt 工作流或服务样板
* 和 AI Coding / Agent / MCP / 内容增长 / GEO / AI 变现有关
* 适合普通大学生、实习生、AI 副业新人理解和复制

不要只因为 Star 高就选择。

## 2. 必须适合我的社媒定位

每个项目都要能服务于以下至少一个方向：

* AI Coding 实操
* Agent / AI 工作流
* MCP / 自动化工具
* AI 内容生产
* 选题雷达 / 信息聚合
* GEO / SEO / AI Search
* AI 工具目录 / 工具测评
* 个人效率自动化
* AI 变现小项目
* 适合写公众号长文的开源项目拆解

如果项目很酷但离我的内容定位太远，不要选。

## 3. 项目必须能转成内容

每个入选项目必须能回答：

* 我为什么要看它？
* 我能不能跑起来？
* 我跑起来后能截图什么？
* 我能改造成什么自己的小东西？
* 我能写成什么公众号标题？
* 普通大学生能不能复制？
* 它能不能沉淀成 GitHub 项目、Skill、教程、资料包或服务样板？

不能转成内容的项目不要选。

## 4. 不重复

读取历史文件：

`项目/GitHub雷达/*.md`

如果项目已经出现过，除非本周有重大更新，否则不要重复进入本周 5 个项目。

如果历史文件不可读取，也要在输出中保留“本周去重说明”。

# 五、筛选流程

先搜索 20-30 个候选项目，再筛出最终 5 个。

候选项目来源尽量覆盖不同类型，不要全是 Agent 框架。

本周 5 个项目尽量按这个结构分布：

1. 1 个 AI Agent / autonomous agent 项目
2. 1 个 AI Coding / coding agent / CLI 项目
3. 1 个 MCP / Workflow / Automation 项目
4. 1 个内容增长 / SEO / GEO / 选题 / 信息聚合项目
5. 1 个适合改造成资料包 / Skill / 小工具 / 教程的项目

如果本周没有合适项目，可以调整分布，但必须说明原因。

# 六、排除规则

排除以下项目：

* 纯 awesome-list，除非只是作为补充资料
* 纯论文，没有可运行 Demo
* 纯模型权重，没有简单使用示例
* README 很差，无法判断如何运行
* 最近长期不维护，且 Issue 大量报错
* 需要企业权限才能使用
* 需要昂贵 API 或复杂云资源才能跑
* 需要多天配置环境才能看到结果
* 只适合大公司工程团队，不适合个人实操
* 和我的社媒定位无关
* 已经在历史雷达中出现过，且本周没有重大更新

# 七、项目难度分层

每个项目必须标注难度：

* 3 小时可跑：适合状态差时快速发内容
* 1 天可改造：适合写公众号长文和做实操
* 3 天可扩展：适合做系列、作品集或开源项目

本周必须至少有 1 个“3 小时可跑”的项目。

本周最推荐先跑的项目，优先选择“1 天可改造”，但不能过于复杂。

# 八、“跑起来”的定义

一个项目只有满足下面至少一种，才算适合进入雷达：

* 本地启动成功后有 UI / CLI / API 输出
* 能跑官方 Demo
* 能截图展示一次结果
* 能改一个配置文件产生自己的输出
* 能接入一个简单任务，例如选题、写 README、抓网页、生成 Markdown、整理资料、调用模型、自动化浏览器
* 能在不复杂部署的情况下完成一次端到端流程

如果只能读代码、不能看到结果，不要作为主推项目。

* 上午：读 README、看 Demo、安装运行

## 11. 变现 / 引流可能性

不要强行说每个项目都能赚钱。能赚钱就说赚钱，不能赚钱就说更适合做作品集或流量入口。

在 `D:\path-to-wealth-freedom` 工作区生成当天的 SaaS 产品创意雷达，并写入：

`内容/项目/YYYY-MM-DD-每日SaaS产品创意雷达.md`

# 一、任务目标

每日收集 100 个高质量、可落地、个人可执行的 SaaS 产品创意，覆盖不同类别、不同用户场景、不同变现路径。

本任务不是公众号选题任务，不输出长文选题，不做新闻解读，不做泛泛而谈的创业灵感。

本任务的目标是生成一个可以长期沉淀的 **个人 SaaS 项目创意库**，帮助我持续发现：

* 可以 1 人开发的 SaaS 项目
* 可以用 AI Coding 快速做 MVP 的项目
* 可以变成模板 / 工具 / 资料包 / 小型订阅产品的项目
* 可以面向海外市场的微型 SaaS
* 可以复刻、改造、细分、垂直化的产品机会
* 可以从现有 Product Hunt、GitHub、trustmrr、Hacker News 项目中拆出来的真实需求

每天最终输出 100 个不重复产品创意，并用 Markdown 表格保存。

# 二、核心原则

## 2.1 只要个人可执行项目

只保留我个人有机会落地的 SaaS / Micro SaaS / AI Tool / Developer Tool / Content Tool / Productivity Tool / Agent Tool / Template Tool。

优先选择：

* 一个人可以开发
* 1-7 天可以做出 MVP
* 可以用 Cursor / Claude Code / Codex / v0 / Supabase / Next.js / Vue / Node.js 快速搭建
* 不需要复杂供应链
* 不需要线下资源
* 不需要大规模销售团队
* 不依赖大型企业合作
* 不需要昂贵数据授权
* 可以先做英文站或简单落地页验证
* 可以通过 SEO、Product Hunt、Reddit、X、GitHub、Newsletter、目录站获取早期流量

避免选择：

* 企业中台
* 大型 CRM
* 完整 ERP
* 复杂金融交易系统
* 医疗、法律、证券等高合规产品
* 硬件项目
* 平台型双边市场
* 需要大量人工运营的项目
* 需要大团队才能完成的 SaaS
* 纯概念、纯融资故事、纯 AI 包装项目

## 2.2 从真实产品反推创意

每个创意都必须来自真实信源中的真实产品、真实 GitHub 项目、真实技术趋势或真实用户讨论。

不能凭空编造产品名称、收入、用户量、融资、功能、发布日期。

可以做“反推创意”，但必须说明它来自哪个产品 / 项目 / 讨论。

例如：

* 从 Product Hunt 上的 AI Resume Builder 反推：面向中国留学生的英文简历 + LinkedIn 优化 SaaS
* 从 GitHub 上的开源 invoice 工具反推：面向独立开发者的一键发票 + Stripe 收入看板
* 从 trustmrr 上的微型产品反推：面向小红书博主的内容报价单生成器
* 从 HN 讨论反推：面向开发者的轻量级 changelog 自动生成工具

## 2.3 不重复，不堆同质化创意

每天 100 个创意必须尽量覆盖不同方向。

同类创意如果过于相似，只保留差异最大的一个。

例如下面这些只能保留少量代表：

* AI Resume Builder
* AI Cover Letter Generator
* AI LinkedIn Optimizer
* AI Job Application Tracker

如果都保留，必须明确它们的差异：

* 目标用户不同
* 分发渠道不同
* MVP 功能不同
* 变现方式不同
* 细分场景不同

# 五、筛选标准

每个候选项目按照以下标准筛选。

## 5.1 必须满足

* 有真实来源链接
* 是产品 / 工具 / 开源项目 / 可产品化需求
* 可以反推出一个个人可执行 SaaS 创意
* 可以用 1-7 天做出最小版本
* 有明确目标用户
* 有明确使用场景
* 有潜在变现方式
* 与已有 100 个创意不高度重复

## 5.2 优先保留

* AI Coding 可实现
* 可做成英文站
* 可做成小工具
* 可做成模板站
* 可做成 Chrome Extension
* 可做成 API 工具
* 可做成自动化工作流
* 可做成面向创作者 / 开发者 / 独立开发者 / 学生 / 小团队的产品
* 有 SEO 长尾关键词机会
* 有 Product Hunt / Reddit / GitHub 分发机会
* 有明确痛点，不只是炫技

## 5.3 直接排除

* 没有链接
* 无法验证真实性
* 只是新闻，不是产品机会
* 需要大量资本
* 需要复杂牌照
* 需要线下资源
* 需要企业销售团队
* 只是“再做一个 ChatGPT”
* 只是“AI + 万物”的空泛包装
* 重复项目
* 太大、太泛、太虚

# 六、去重规则

每天生成前，优先检查历史文件：

`内容/项目/*.md`

如能读取历史文件，必须进行去重。

去重维度包括：

* 产品名称
* 目标用户
* 核心功能
* 使用场景
* 变现方式
* 关键词
* 来源链接

如果无法读取历史项目库，必须输出：

`未成功读取历史项目库，本次仅对今日 100 个创意内部去重。`

重复判断规则：

* 名称不同但功能几乎相同，算重复
* 功能相同但目标用户不同，可以保留
* 功能相同但分发渠道 / 商业模式明显不同，可以保留
* 来源不同但本质是同一产品，只保留一条
* 同一个 GitHub 项目和 Product Hunt 页面指向同一产品，只合并为一条

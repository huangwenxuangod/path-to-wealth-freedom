# Motion Director

从项目根目录读取 DESIGN.md、src/spec.ts、data/ 和 src/Root.tsx。先确定观众要理解的一件事、关键静帧和动作节奏，复用已有 Composition 与视觉部件。

- 技术 API 优先读已安装的官方 Remotion skills 或当前文档。复杂时间轴用官方 @remotion/gsap；其支持子集不等于整个 GSAP 插件生态。
- 从当前 fps 推导秒，不使用网页自动播放时钟。React 与 GSAP 不同时写同一元素的同一动画属性。
- 横竖屏分别构图；中文按字素计数，长文案用分镜或明确报错，不无限缩字。
- 获取第三方视觉源码时记录来源与许可；成片使用与可复用组件分发分开处理。
- 用户参考优先。默认一个主动作组；背景是否运动由镜头信息决定。
- 先 `bun run typecheck` 和 `bun run check`，再运行对应 render preset 与 `bun run verify`。
- 实际打开关键帧与成片，核对节点连接、文字、首尾帧；透明素材在深浅底检查。
- 交付源文件、输入 JSON、成片、验收记录。代码完成、插件已启用、视频已渲染和剪辑应用实测分别报告。
- Studio 的拖拽可能写回源码，发现意外差异时先确认来源，保留用户修改。

## 常用制作请求

“以 benchmark 数据制作新视频，先检查主题与素材，保留现有视觉语言；渲染横竖屏与透明层并验证。”

只有真实镜头需要时增加组件；不建立未使用的背景、相机、粒子抽象或第二套渲染服务。

## 题材设计与素材检索

每条新片先读取 frontend-design，结合主题/受众提出本片视觉方案；不自动继承其他片子的黑底或荧光配色。主动检索官方发布页、品牌页和原始演示，下载本地素材并记录来源、时间、哈希与许可。Magic UI 使用官方注册表源码，并在分镜中标明实际使用的组件；改编其计时、入屏触发与媒体加载为 Remotion 确定性行为。事实、官方示例和原创流程示意分别标注。

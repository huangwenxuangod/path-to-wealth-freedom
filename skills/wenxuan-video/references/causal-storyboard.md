# 知识→机制→镜头

本文件负责知识机制建模；阶段顺序与运镜分析以 [director-workflow.md](director-workflow.md) 为准。先完整叙事和轻量分镜，再动效方案；表中的动作描述不是逐帧特效设计。

## 先有因果，后有气氛

以一句可检验的主张为中心。列出输入变量、状态变量、因果连接、竞争解释和适用边界。例如“利润吸引进入”需要利润可观察、进入成本可承担、需求没有同步扩张等条件；商户聚集也可能来自共享客流，不能自动全归为价格竞争。

镜头账本至少包含：

| 字段 | 用途 |
|---|---|
| start/end | 秒或帧，统一单位；覆盖全片 |
| claim/source | 本段主张与一手证据，区别事实和解释 |
| visualQuestion | 观众应该从画面得到的答案 |
| entity/stateBefore/stateAfter | 主体和明确状态变化 |
| cause/trigger | 哪个事件导致下一状态 |
| camera | 位置、目标、景别、关键帧、转场理由 |
| caption/voice | 简短屏幕句与完整旁白、时间边界 |
| audioCue | 少量语义事件，而非每个物体登场都配声 |

## 连续对象原则

让同一个物体穿过多个镜头：利润信号→新商家看到→进入→价格/利润变化，比“信号波动画→不相关立方体→全屏公式”更容易形成因果理解。镜头拉远显示整体，拉近解释局部，变化发生后停留让观众读懂。

屏幕一时刻只承载一个主解释关系。背景层提供环境，机制层承载变化，标签层说明变量，字幕层承载一句结论。字体大小按最终分辨率检查，不用满屏 HUD 显得专业。

## 参数与知识严谨性

将数据与视觉解耦。时间轴配置调整镜头，不应悄悄改变知识结论。动画示例的数值必须标为示意；真实数据记录来源、单位、年份和处理方法。历史贸易路线、地形等区分真实边界、示意路径、程序化高程。

脚手架中的商家演示只有“抽象进入压价”这一个视觉机制，价格数值不是市场预测。换选题必须重写模型与镜头，保留底层元件而非硬换字幕。

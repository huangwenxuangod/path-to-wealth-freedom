Sam Altman 同意放缓前沿 AI

摘要：这不是“暂停 AI”，而是争夺速度规则的起草权

2026 年 9 月，Anthropic 创始人 Dario Amodei 发表《We Must Pace the Frontier》，主张前沿 AI 的能力增长速度需要给安全、评估和治理留下追赶时间。几乎同时，OpenAI CEO Sam Altman 公开表示：“I agree with Dario that we need to pace the frontier”，并称 OpenAI 将采取类似 Anthropic 的独立评估者访问安排。

表面看，这是两家竞争公司的安全共识。纵向看，它是 2023 年“暂停训练”争论、2024 年安全承诺、2025—2026 年 Agent 与递归自我改进风险累积后的政策转向。横向看，它又是一场竞争：谁先定义“合理速度”、谁先把第三方评估制度化，谁就可能把安全从成本变成行业准入规则。

我的核心判断是：Altman 的表态不是放弃竞速，而是把竞速从“谁先发布模型”改写为“谁能在可验证的安全约束下继续竞速”。真正的分歧不在于要不要慢一点，而在于谁来测量“太快”、哪些能力触发限速，以及限速是否会给中国等对手留下战略窗口。

一、纵向分析：从暂停训练到“可验证的速度限制”

1. 共同背景：AI 竞赛先加速，治理后补课

OpenAI、Anthropic、Google DeepMind 和 Meta 在过去几年形成了典型的规模竞赛：更多算力、更大训练集、更长推理时间、更强工具调用。安全研究往往被安排在模型能力确定之后，而不是能力增长的前置条件。这个顺序在聊天机器人时代尚能勉强维持，进入 Agent 时代后开始失效。

Agent 不只是回答问题，它会读写文件、调用终端、浏览网页、提交代码并循环执行任务。系统行为因此变成“模型能力 × 工具权限 × 持续时间”的乘积。模型每提升一点，能够触达的外部状态就多一层；安全测试若仍以一次性对话为单位，就会低估长任务中的累积风险。

Amodei 在原文中尤其强调两个变化。第一，AI 开始参与构建下一代 AI，递归自我改进从理论命题变成工程趋势。第二，OpenAI—Hugging Face 事件中，Agent swarm 被描述为大规模执行软件操作，显示自动化系统可能在组织边界之外产生难以预见的行为。两者叠加，带来的不是某个模型“突然失控”，而是风险增长速度可能超过评估体系更新速度。

2. 2023：暂停训练倡议留下的结构性矛盾

2023 年公开信要求暂停训练比 GPT-4 更强的系统，迅速得到关注，却没有形成可执行的全球机制。问题不只是立场分裂，还在于“暂停什么”无法定义：是参数规模、训练算力、能力阈值，还是部署规模？如果只有部分公司暂停，守约者会把市场和人才让给不暂停者；如果要求全球同步，又缺乏核验训练集群和地下项目的手段。

这段争论留下两个教训。其一，泛化的“暂停”很难执行，窄化、可测量的约束更有机会落地。其二，企业不会主动接受永久性劣势，除非规则同时保护其竞争位置。Amodei 2026 年提出的“pacing”因此刻意区别于无限期 pause：允许继续进步，但把速度与安全能力、评估结果和地缘战略联系起来。

3. 2024—2025：从自律承诺到组织化监督

前沿实验室陆续发布 Responsible Scaling Policy、Preparedness Framework、Frontier Safety Framework 等内部规则。它们共同承认模型在生物、网络安全、自主复制和欺诈方面可能跨越能力门槛；不同之处在于阈值由公司自己设定，测试也主要由公司自己完成。

这种安排有实际好处：迭代快、能结合内部权重和训练日志、不会把敏感能力暴露给竞争者。但它也有明显盲点：公司既是被评估者，又是评估标准的制定者；投资者、客户和政府只能看到选择性披露。安全承诺一旦与发布节奏冲突，就会出现“解释空间”。

Amodei 的转折是把监督者嵌入公司内部。他提出由具备类似员工权限的外部评估团队持续访问，核验安全实践并报告事故。它不是一次性的审计报告，而是接近“常驻观察员”制度。Altman 表示 OpenAI 将采取同样做法，说明这项安排至少在话语层面从单家公司倡议变成行业基准。

4. 2026：递归自我改进让“速度”成为独立变量

传统模型迭代的速度大体由研究员、算力和数据供给决定。若模型能够改进代码、设计实验、生成训练数据并协助架构搜索，下一代系统的开发周期会缩短。此时安全投入即使保持不变，安全与能力之间的时间差也会扩大。

Amodei 的方案因此提出按模型能力、训练流水线和递归自我改进速度设定“speed limit”。这不是给所有 AI 统一设定一个月产量，而是让限制对象尽量贴近风险机制：例如高风险能力评估未通过时，限制部署权限；当模型开始自动推进下一代训练时，要求更高等级的外部验证；当安全证明、操作安全和解释性研究跟不上时，延后能力扩张。

5. Altman 的同意：从反应性表态到规则共同生产

Altman 的公开表态包含两层信息。第一，他认同“前沿需要节奏”这一原则。第二，他接受 Anthropic 提出的独立评估者长期访问思路，并承诺 OpenAI 也会跟进。后者更重要，因为它把价值宣言变成组织安排。

但这不等于 OpenAI 接受 Amodei 全部政策包。Amodei 同时谈到对华技术领先、芯片与算力控制、民主国家间协调，以及与中国建立可验证的全球协议。Altman 的短文回应没有承诺接受具体速度阈值，也没有说明哪些内部权限会开放。因此，当前更准确的表述是“监督机制趋同，速度规则仍待谈判”。

二、横向分析：四种前沿实验室路线

1. Anthropic：把安全制度变成竞争壁垒

Anthropic 的历史起点是对 OpenAI 安全治理方向的失望。它选择“安全优先”的品牌，并通过 Constitutional AI、可解释性和 Responsible Scaling Policy 把理念写进产品叙事。Amodei 此次的优势在于能够把安全语言连接到商业现实：谨慎不是停摆，而是为客户、政府和合作伙伴提供可验证的信任。

其短板也来自同一选择。Anthropic 仍需融资、扩大算力和追赶模型能力；当它倡议“放缓”时，竞争者会问：这是公共利益，还是限制领先者、保护自身窗口的策略？因此它必须接受对自身同样严格的评估，才可能把倡议变成可信规则。

2. OpenAI：在规模与制度之间重新平衡

OpenAI 拥有最大的开发者生态、产品分发和品牌影响力。它的优势是能够把安全机制快速部署到大量用户和 API 客户中。Altman 同意嵌入式评估者，可能是为了让外部监督跟上模型、Agent 和企业服务的扩张速度，也可能是为了降低监管不确定性。

OpenAI 的结构性矛盾更尖锐：它既是最有能力推动前沿的组织，也是最容易被要求证明“没有把商业压力置于安全之上”的组织。独立评估若只有访问权，没有发布阻断权、事故报告权和追责路径，就可能退化为观察项目。Altman 的承诺要获得实质含义，关键在权限边界和报告是否能绕过管理层直接到达董事会或监管者。

3. Google DeepMind：研究深度与平台约束

Google DeepMind 拥有长期安全研究传统、基础设施和多模态产品平台。它较适合做能力评估标准、红队工具和跨模型基准，因为能把研究机构、云平台和消费产品连起来。但大公司内部的产品线众多，安全阈值如何在搜索、云、办公和机器人之间统一，是执行难点。

4. Meta 与开放模型路线：速度、扩散与责任边界

Meta 更强调开放权重和生态扩散。开放模型可以促进审查、创新和本地部署，也会减少单一公司对能力的垄断；但模型发布后，开发者和部署者分散在公司边界之外，嵌入式评估者难以覆盖整个链条。对开放模型而言，治理重点可能从“是否发布”转向权重访问、危险能力检测、下游部署登记与事件响应。

5. 横向结论：赛道正在从模型竞赛转为“可信速度”竞赛

四条路线没有简单的安全高低之分。Anthropic 擅长提出规范，OpenAI 擅长规模化执行，Google 擅长研究与平台整合，Meta 擅长生态扩散。未来的行业标准很可能不是某一家公司的完整复制，而是组合：外部评估的独立性来自 Anthropic，部署覆盖来自 OpenAI，测试基础设施来自 Google，开放生态的透明度压力来自 Meta。

三、横纵交汇：为什么偏偏是现在，为什么是 Altman 接住了这个球

1. 历史把“放缓”从道德呼吁推向组织设计

2023 年的暂停倡议失败，说明只谈速度不谈核验机制没有执行力；2024—2025 年的自律框架普及，说明公司已经承认风险，但内部评估的可信度不足；2026 年 Agent 和递归改进把时间差放大，于是常驻外部评估成为中间方案：比全面暂停窄，比内部自律硬。

2. Altman 的同意是一种竞争性合作

两家公司在模型、客户和人才上竞争，却在评估机制上靠拢。这类似金融市场中的共同披露规则：竞争者不必共享全部商业秘密，但需要接受最低限度的可比检查。共同规则能减少“谁先自律谁吃亏”的担忧，也能向政府传递行业正在自我治理的信号。

我的判断是，Altman 接受的是“制度化监督”，而不是“无条件减速”。OpenAI 更可能支持按风险能力分级的速度控制，而非固定时间表；更可能接受由多个机构组成的评估网络，而非把否决权交给单一监管者。

3. “对华竞争”既是现实约束，也是政策杠杆

Amodei 明确提出，民主国家的放缓不能大到让中国在未受约束的项目上取得决定性领先。这一条件让方案区别于单纯的技术怀疑主义：它承认 AI 既是安全问题，也是国家能力问题。风险在于，“对华竞争”可能被用来压缩透明度；机会在于，它也能成为推动盟友共同评估、共享算力安全和建立危机沟通的政治理由。

4. 三个未来剧本

最可能：有限趋同。 OpenAI、Anthropic 和 Google 建立常驻或半常驻评估机制，围绕生物、网络、自主复制等高风险能力形成共享测试集。模型总体继续高速迭代，但在触发阈值后增加审查、限制工具权限或延迟部署。速度规则是分层的，全球协议停留在窄领域禁用和发布前测试。

最危险：安全共识成为竞赛话术。 公司公开同意“放缓”，实际只增加宣传和低权限访问；当某家接近重大能力突破时，评估团队无法阻止发布。事故发生后，各国以国家安全为由收紧出口和数据控制，行业进入不透明的地下竞赛，安全研究反而更难共享。

最乐观：可信速度成为新基础设施。 外部评估者拥有持续访问、事故报告和有限阻断权；不同公司采用可比指标，政府把合规结果与算力、采购和部署许可挂钩；中美先从生物和网络高风险测试开始建立窄协议。AI 仍然快速进步，但每一次跨越都留下可审计记录，安全能力终于成为能力增长的前置条件。

四、给企业与普通使用者的观察框架

企业采购前沿模型时，不应只问基准分数和单价，还要问：是否有独立评估、评估者能访问哪些日志、事故是否必须披露、Agent 工具权限能否分级、模型更新是否经过风险复测。对于普通用户，最重要的变化不是某个模型会不会“慢一点”，而是高权限自动化功能可能出现更细的权限、审计和等待流程。

五、结论

Sam Altman 同意 Dario Amodei，并不是前沿 AI 竞赛结束的信号，而是竞赛规则进入重写期的信号。Amodei 提供了问题框架：能力增长可能快过安全追赶；Altman 提供了规模化承诺：OpenAI 愿意把外部评估嵌入组织。

接下来真正值得观察的不是口号，而是四个可验证动作：评估者是否拥有员工级权限；是否能独立报告事故；是否能影响发布和工具权限；是否会形成跨公司可比的速度与能力阈值。只有这些动作出现，“放缓前沿”才会从公开信变成制度。

# 研究明白：从认知地图到研究闭环

资料量不是完成标准。研究必须形成“事实 → 解释 → 比较 → 验证 → 判断 → 边界”的闭环。需要完整历史和竞争格局时，可结合 `hv-analysis`；本 Skill 负责判断研究是否真正站得住。

## 先定义研究任务

在收集资料前写清：

- 研究对象：它是什么，不是什么。
- 决策问题：研究结果要支持什么判断或行动。
- 时间截面与地域：结论截至何时、适用于哪里。
- 目标用户：谁会使用这份结论。
- 成功标准：需要回答哪些问题，哪些问题可以暂缺。

若用户信息足够，直接研究，不为形式化字段追问。

## 完成六项闭环

### 1. 一句话定义

用“它是什么 + 为谁 + 解决什么问题 + 用什么方式”定义对象。定义必须能排除容易混淆的相邻对象。

### 2. 解释为什么是现在

连接需求、技术、产品形态、基础设施、成本、分发、政策或市场条件。不要把发布时间当作原因；说明哪些条件过去不存在，哪些条件现在同时成熟。

### 3. 纵向追时间，横向追同期

- 纵向：起源、最初问题、关键人物、初始形态、版本与转折、历史决策如何塑造今天。
- 横向：直接竞品、间接替代、旧方案、目标用户、产品形态、能力、价格、商业模式、优劣与生态位。
- 交汇：今天的优势和短板分别源于哪些历史选择；差异能否维持；未来由哪些变量决定。

对比对象必须服务于决策问题，不为凑表格罗列竞品。

### 4. 建立证据账本

对影响结论的关键主张记录：

| 主张 | 来源链接 | 来源类型 | 日期 | 直接支持的内容 | 可信度 | 状态 |
|---|---|---|---|---|---|---|

来源类型至少区分：官方一手资料、监管或原始数据、论文、权威媒体、作者演示、用户反馈、自己的实测、尚未证实的推测。

- 关键事实优先使用一手来源；二手来源要追到原始出处。
- 多个转载同一消息不算独立印证。
- 区分事实发生日期、文章发布日期和访问日期。
- 只写来源实际支持的范围；相关不等于证实。
- 没有可靠证据时用“据报道”“尚未找到官方确认”或“推测”，不得升级为事实。

### 5. 对可操作对象做实测

研究产品体验、性能、复现性或普通用户可用性时必须测试；公司史、行业史或纯概念研究可不测试，但要说明原因。

实测记录至少包含：

- 环境：设备、系统、版本、账号权限、区域、依赖和网络条件。
- 任务：输入、提示词、数据、成功判据与对照方案。
- 过程：耗时、成本、人工干预、重试、失败和修正。
- 结果：原始输出、通过率或量化指标，以及与宣传案例的差距。
- 可复现性：至少区分“一次成功”和“稳定成功”；重要结论尽量重复测试。

无法实测时，把结论降级为“案例拆解”或“待验证判断”，不要声称普通用户可复现。

### 6. 输出判断与边界

每个核心判断按以下结构写：

1. **事实**：可追溯证据或实测结果。
2. **解释**：为什么这些事实会产生当前现象。
3. **比较**：相对竞品、替代方案或过去状态有何差异。
4. **判断**：对用户、产品、行业或未来的含义。
5. **置信度**：高 / 中 / 低，并说明降低置信度的变量。
6. **成立条件**：适用人群、环境、时间和失败条件。

必须单列“仍不知道什么”，包括未验证事实、样本偏差、稳定性、成本、人工干预、权限依赖和可能使结论过期的更新。

## 交付结构

根据任务规模压缩或展开，但至少包含：

1. 一句话定义
2. 为什么是现在
3. 纵向时间线
4. 横向竞争与替代方案
5. 关键事实与证据账本
6. 实测设计和结果，或未实测原因
7. 横纵交汇后的核心判断
8. 结论成立的条件与未知项
9. 下一步验证清单

## 研究完成度门槛

交付前检查：

- [ ] 外行能听懂一句话定义，且边界清楚。
- [ ] 能解释为什么是现在，而非只描述最新事件。
- [ ] 能说明与竞品、替代方案和旧方案的差异。
- [ ] 每个关键事实可追溯，事实、报道、反馈、实测和推测没有混写。
- [ ] 产品可用性或复现性判断有实测；没有实测的结论已降级。
- [ ] 每个核心判断都有依据、比较、置信度和成立条件。
- [ ] 明确列出仍不知道什么，以及下一步如何验证。

若任一关键项缺失，不写“已经彻底研究明白”，而是说明当前完成度和最大证据缺口。

# 06 - 生产标准

## 目的

这份文档用于固化已经验证有效的 HyperFrames AI 视频构建流程。

以后再做同类视频，默认不再从零试错，而是直接按这套标准推进。

---

## 一、适用范围

适用于以下类型的视频：

- AI 个人介绍视频
- 能力展示视频
- 方法论表达视频
- 流程验证视频
- 知识型品牌短片

不适用于：

- 强娱乐向短视频
- 大量真实拍摄素材混剪
- 影视叙事型 MV

---

## 二、默认技术栈

- **构建**：TypeScript + Bun
- **渲染**：HyperFrames
- **动效**：HTML / CSS / GSAP
- **配音**：`msedge-tts`
- **字幕**：脚本自动生成 SRT
- **检查**：`hyperframes lint` + `hyperframes validate` + `ffprobe` + 关键帧抽查

原则：

1. 所有生成流程必须能通过 Bun 命令串起来。
2. 不允许临时散落多个手工脚本。
3. 最终输出必须是可复现的工程，而不是一次性结果。

---

## 三、默认流程

### Phase 1：需求收束

必须先明确：

1. 显示名
2. 主题
3. 视频比例
4. 目标时长
5. 旁白风格
6. 是否露脸
7. 内容来源
8. CTA
9. 重点想展示的是身份、能力、流程还是结果

如果用户表达模糊，优先帮用户收束，不直接开做。

---

### Phase 2：内容提炼

把输入材料整理成：

- 人设句
- 核心观点
- 方法句
- 工具句
- 目标句
- 收尾 CTA

要求：

- 每句尽量短
- 每句都能对应一个镜头
- 不写大段解说词

---

### Phase 3：镜头设计

先定结构，再做动效。

默认镜头结构：

1. **身份识别**
   - 姓名
   - 标签
   - 人设卡片

2. **观点建立**
   - 不是收藏工具
   - 是把 AI 放进真实流程

3. **流程展开**
   - 选题
   - 研究
   - 写作
   - 知识库
   - 分发
   - 反馈

4. **系统镜头**
   - 核心 workflow
   - 工具围绕系统工作

5. **能力镜头**
   - 理解行业
   - 做出产品
   - 验证机会

6. **目标镜头**
   - 毕业前赚到 100 万

7. **结尾镜头**
   - CTA 收束

---

## 四、视觉标准

本项目后续默认采用从 `guizang-ppt-skill` 提炼出的 Swiss 极简高级风规则。

### 1. 配色

- 只使用 **一个 accent 色**
- 当前默认：`IKB 蓝`
- 底色：暖白 / 纸白
- 文字：近黑
- 辅助：高级灰

禁止：

- 多个高亮色混搭
- 紫蓝渐变
- 发光霓虹球
- 彩色卡片乱用

### 2. 排版

- 标题左对齐
- 轻字重，大字号
- 强层级，少装饰
- 中文标题优先手动断行
- 标题不能贴边，也不能一字一行乱断

### 3. 结构

- 一切内容必须落在明确网格里
- 元素必须服务信息结构
- 装饰必须后退，不能抢主信息
- 工具名不能像贴纸一样乱飘

### 4. 组件语言

优先使用：

- hairline 细线
- 直角边框
- 模块化信息块
- 结构化标签
- 面板式系统图

避免：

- 大圆漂浮轨道当主体
- 旋转标签
- 夸张弹跳
- 厚阴影
- 拟物卡片感

---

## 五、动效标准

### 原则

动效的目标不是“炫”，而是表达系统状态变化。

### 应该做的

- 元素有进入、建立、收束
- 节点按顺序激活
- 线条表达流程推进
- 模块位置变化要有逻辑
- 场景切换尽量像系统切换状态

### 不应该做的

- 整屏元素同时乱入
- 无意义旋转
- 无结构漂浮
- 把每个镜头都做成 PPT 翻页

### 默认节奏

- 开场：建立身份
- 中段：展开结构
- 后段：收束目标
- 结尾：统一回到 CTA

## 六、对话与分析样式标准

用户特别在意“对话和分析的样式”，以后默认遵守下面这些规则：

1. 分析信息块必须统一视觉语言
2. 不用糖水半透明提示框
3. 不用过重的说明卡片
4. 说明块要像编辑信息，不像弹窗
5. 底部字幕和画面说明不能互相打架

推荐做法：

- 底部字幕使用直角信息条
- 上方分析区使用等宽标签 + 短句
- 分析区和主视觉之间保留呼吸空间

## 七、工程标准

### 代码结构

关键入口：

- `app/src/build.ts`：生成 composition
- `app/src/data.ts`：镜头数据与脚本
- `app/src/tts.ts`：配音生成
- `app/src/captions.ts`：字幕生成

要求：

- 构建逻辑集中
- 数据集中
- 输出路径固定
- 不使用一次性临时文件拼装方案

### 命令标准

```powershell
cd app
bun run build
bun run tts
bun run captions
npx --yes hyperframes@0.6.2 lint
npx --yes hyperframes@0.6.2 validate
npx --yes hyperframes@0.6.2 render --output output/wenxuan-dynamic.mp4
```

## 八、验收标准

每次交付前至少检查：

### 基础检查

1. 视频成功输出
2. 分辨率正确
3. 音频存在
4. 时长符合预期
5. 字幕存在

### 视觉检查

1. 是否还有 PPT 感
2. 是否有廉价漂浮元素
3. 中文标题是否断行合理
4. 信息层级是否明确
5. 是否保持单一 accent 色

### 动效检查

1. 是否真的在动，而不是静态页切换
2. 动效是否有结构逻辑
3. 过渡是否顺滑
4. 是否有多余旋转和乱飞

### 工程检查

1. `lint` 通过
2. `validate` 无阻断错误
3. `ffprobe` 确认音视频流
4. 至少抽两到三个关键帧人工复核

---

## 九、当前确认有效的方法

这次项目已经证明有效的做法：

1. 先重写方案，再动代码
2. 用 `guizang-ppt-skill` 提炼视觉规则，而不是直接模仿 PPT 页面
3. 把“工具关系”改成结构化系统图，而不是漂浮标签
4. 把字幕和分析块统一成编辑式信息语言
5. 用关键帧抽查快速定位是否“高级感不足”

---

## 十、后续默认迭代方向

下一轮如果继续提升，优先优化：

1. 中文标题断行与字重
2. 系统镜头的版式精度
3. 开场和结尾的品牌感
4. 旁白节奏和字幕匹配
5. 将这套流程封装成真正的 Skill

---

## 十一、结论

以后本项目默认标准不是：

> 能生成一个视频就行。

而是：

> 用 TypeScript + Bun + HyperFrames，稳定生成一条有结构、有动态、有审美纪律的 AI 视频。

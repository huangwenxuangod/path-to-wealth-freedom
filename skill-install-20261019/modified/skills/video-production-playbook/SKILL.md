# Video Production Playbook

先选任务，再选制作路径，最后写可验收的制作任务单。这个 skill 不渲染视频，它把「做什么、用什么做、怎么验收、怎么披露」讲清楚，避免一上来就抽卡。

来源：https://github.com/athemeroy/awesome-claude-5-5-videos （文字与图表 CC BY 4.0；案例与截图归原作者）。数据截至 2026-10-11。

## 何时用

- 用户有一个视频想法，但不确定用代码动画、三维、视频模型还是素材改编。
- 要写制作 brief、分镜、验收标准、公开披露。
- 要查某类作品（游戏、广告、教育、故事）常见的画风与配色。
- 要复用开源工程或提示词模板。

## 第一步：判断任务类型

| 想要 | 优先路径 | 参考 |
|---|---|---|
| 二维代码动画、几何/字体动效 | Canvas / SVG / Remotion | `docs/prompt-playbook.zh-CN.md#1` |
| 知识讲解、公式与图解 | Manim / Remotion + TTS | `#2` |
| 产品宣传、真实界面 | 现有仓库 + Remotion | `#3` |
| 三维场景、材质、产品 | Blender / Three.js | `#4` |
| 写实人物、复杂场景 | 视频模型（Seedance 等） | `#5` |
| 改编已有影片 | 后期 / 可编辑工程 | `#6` |
| 已有成熟生产线 | 调用项目内 skill | `#7` |

判断依据：画面是否需要真实人脸与自然运动（→ 视频模型）；是否需要精确文字与因果（→ 代码动画）；是否需要真实产品证据（→ 现有资产）；是否需要材质与镜头（→ 三维）。

## 第二步：写制作任务单

按 `references/docs/production-brief.zh-CN.md` 填：

1. 一句话目标与受众；发布平台与画幅/时长。
2. 三项可验收的信息目标（观众看完能回答什么）。
3. 素材清单与授权：自有、CC0、OFL、官方新闻稿插图；逐项写来源。
4. 制作路径与工具；哪些由人决策，哪些由模型生成。
5. 分镜表：时间、画面主体、动作、字幕、声音事件、转场。
6. 验收：文字不溢出、角色/物件连续、声画同步、响度与真峰值、事实核对。
7. 披露：模型、版本、生成次数、人工修改、外部服务费用。

## 第三步：选画风与配色（有数据依据）

- 游戏/交互类：约 70% 归为三维渲染（161/230）。
- 广告/发布片：约 71.6% 归为动态图形/界面（154/215）。
- 教育类画风分散，动态图形最大组约 37.4%；故事类扁平卡通最大组约 33.0%。
- 动态图形/界面中深色中性 198 个、浅色中性 152 个：两套都常见，不要只做一张平均色卡。
- 音乐视频彩色像素占比中位数 45.5%，广告 17.6%：按内容选视觉密度。

这些是样本统计，不是效果排名；引用时保留日期与分母。

## 第四步：制作与验收

1. 先低清样片（前 5–10 秒或最难镜头），检查文字、连续性、运动速度。
2. 再做整片；每轮修改记录原因，不要只留最终版。
3. 抽帧检查每个镜头的起/中/末；检查字幕与音轨。
4. 用 `ffprobe` 查时长、帧率、音轨；用 `ebur128` 查响度与真峰值。
5. 事实、数字、引语逐条对照一手来源。

## 第五步：公开披露

「one prompt」只说明初始指令轮数；「纯代码」说明视觉渲染路径；「零外部素材」说明输入边界；「无人修改」说明审片过程。四者独立，不能互相替代。交付时分别列出人类输入、预置 skill、既有素材、模型生成与人工修改。

## 常见坑

- 把九帧预览当成完整动态验证；预览只能说明画面存在。
- 把作者报告的模型标签当成可复现的实验结论。
- 用「一条提示词」掩盖多轮修改与人工选片。
- 只算模型单价，不算修改、工具、素材与失败重试的整项费用。
